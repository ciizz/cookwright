# cookwright

This repo builds cookwright, an agentic harness for solo mobile developers. Read `CHARTER.md` first; it is authoritative on what the product is and is amended only by a dated entry.

## This repo eats its own cooking

The repo's own harness config (this file, the hooks, the bundle runner, `docs/dev/`) is cookwright applied to cookwright. The template a user receives is generated by the package from `packages/cookwright`, never copied from this file.

## Layout

- `packages/cookwright/` — the npm package: everything a user installs. `lifted/` holds files copied verbatim from Leeka awaiting extraction; it must be empty before v1.
- `packages/cookwright/hosts/` — the files a host's adapter ships, per host (`claude/workflows/`; Codex has no workflows, so its adapter is code only, under `src/lib/`); `packages/cookwright/skills/` the skills, host-agnostic (`setup`, `bundle`); `packages/cookwright/docs/playbook.md` the bundle playbook. All three ship in the tarball.
- `.claude/` — the pointers `npx cookwright init` writes (`skills/<name>`, `workflows/<name>.js`), symbolic links into `node_modules/cookwright`, here the workspace link to the package. Tracked; init rewrites them, never edit them by hand.
- `scripts/ci/fixture.sh` — the harness fixture, `bash scripts/ci/fixture.sh`: a pinned `create-expo-app` scaffold with `fixtures/expo-overlay/` appended, the package installed from its `npm pack` tarball, then init, doctor, a commit through the hooks, changelog and migrate run against it. The pinned versions are bumped deliberately, by hand. `.github/workflows/ci.yml`, on a push to `main` or a `bundle/**` branch and on a pull request, runs `npm test` (ubuntu and macOS, Node 20 and 22) and the fixture (ubuntu, gitleaks from its pinned release).
- `docs/` — user documentation. `docs/dev/` — kickoffs, closeouts and bundle state for people building cookwright.
- `CLAUDE.local.md` — gitignored, machine-local pointers. Never commit a local path anywhere else.

## Rules

- **Nothing private, ever.** No local paths, no credentials, no details of any specific user's production operations in anything committed. Leeka is the origin story and may be named; its ops, data and paths may not appear.
- **Secrets never touch disk in plaintext.** No `.env` files, no fallback that writes one. A backend injects into one child process with target proof.
- **Every piece is optional.** A check, hook or script that needs a tool the user lacks reports "skipped, needs X, run setup" and exits 0. It never fails on absence.
- **Scripts are imported, not copied.** Nothing the package installs into a user repo is a copy of a script; user repos hold config and thin shims.
- **Stage 0 excepted, work ships as bundles** through the repo's own runner: plan mode first, a written plan, an adversarial review of the plan, implementation, review of the diff, a closeout in `docs/dev/closeouts/`.
- Ask before adding a dependency. Functions under ~40 lines. User-facing strings in one place.

- `docs/dev/closeouts/` — one past-tense file per shipped bundle.
- `docs/dev/bundles/` — bundle state, written only by the runner.

## State homes

Every kind of state has exactly one home. This file is the map, not the store.

- Tasks, bugs and enhancements: the backlog, `docs/dev/backlog.md`.
- What a piece of work did and why: a closeout in `docs/dev/closeouts/`, written once, in the past tense, when the work closes.
- User-visible changes: the subject of a conventional commit (`feat:`, `fix:`, `perf:`; `!` marks a breaking one). `CHANGELOG.md` is generated from release tags by `npx cookwright changelog` and never edited by hand; `npx cookwright changelog --unreleased` lists what is pending.
- Don't record what can be derived. Merge state is git's; test state is the suite's.
- No "pending" or "next steps" narrative in an active doc. A thing to do is a backlog entry.
- Update the state homes at every status change you take part in or learn of.

## Backlog discipline

- A discovery outside the current task's scope is logged, not fixed. A bug goes under "Open bugs" with the next `B-nnn` id, an enhancement under "Open enhancements" with the next `E-nnn`. Ids are stable and never reused.
- The bar: a fix that touches files outside the task's declared surface, or more than about five lines outside its scope, is out of scope. Discoveries made while planning count.
- One line per item, dated when opened. Closing an item moves its line to "Closed" with a one-line note; a commit that fixes an item names its id.

## Doc sync

A change with doc implications updates the doc in the same commit. When unsure whether a doc is affected, update it. The pre-commit hook enforces the rules in `cookwright.json` (`hooks.docSync`). A commit that really has no doc implication goes through with `COOKWRIGHT_SKIP=doc-sync git commit …` and carries the reason in its message, since the escape itself leaves no trace.

## Git hooks

When `npx cookwright init` has installed the hooks (`.githooks/`): pre-commit scans the staged diff for secrets (gitleaks; skipped when it is not installed) and checks doc sync; pre-push runs the gate checks and verifies the changelog. `COOKWRIGHT_SKIP=<check,…>` skips the named checks and says so; `git commit --no-verify` skips everything and is the last resort.

## Session start

`cookwright doctor` runs at session start and its readout is in your context. Deal with a FAIL before any other work. A WARN names its next step: take it, or log it in the backlog. If no doctor line reached you, run `npx cookwright doctor`. On a FAIL whose line does not clear it, on an update, or when the developer asks, the `setup` skill walks doctor's readout.

## Secrets

- Never write a plaintext env file (`.env`, `.env.*`), not as a fallback and not for a test.
- Never put a secret's value in a doc, a commit, a log or a transcript. Name the secret instead.

## Conventions

- Ask before adding a dependency.
- When this file changes mid-session, re-read it.
- Retrospectives go in closeouts, not in this file.
