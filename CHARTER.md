# cookwright — charter

Decided 2026-10-14. This file records the product decisions; it changes only by a dated amendment below.

## What it is

A harness for solo developers building mobile apps with React Native, TypeScript and Supabase, that makes an AI coding agent work the way a disciplined senior engineer would: plan before code, review before merge, docs that cannot drift from code, screenshots regenerated from the real app, deploys that cannot reach the wrong target, secrets that never touch disk. It grew out of the harness built for Leeka, a live React Native app in both stores, and is being extracted into a product any solo dev can install.

A stack-agnostic core (hooks, state homes, backlog, changelog, the bundle runner, the docs audit) sits under a stack pack (screenshot atlas on iOS simulator and Android emulator, OTA fingerprint preflight, Supabase ops with a read-only agent role, encrypted dumps).

## Five properties, ranked

1. **Guided setup.** A user with an Expo app and nothing else reaches a working Level 0 in one sitting. Each external tool (Supabase, a secrets backend, EAS, simulators) is a step the harness verifies before moving on.
2. **Graceful degradation.** Every piece is optional. A missing tool is a known, reported state, never a failing hook or a crashed script.
3. **No rot.** The harness knows its own level, detects drift and anomalies (secret leaks, stale docs, stale screenshots), and suggests the next upgrade on its own. A cheap `doctor` at session start, a deeper docs audit on a schedule.
4. **Updates reach users.** Scripts are imported from the package, never copied into the user's repo. Fixes land by a version bump, with config migrations between versions.
5. **Community.** Open source, testable by strangers, contributions possible without reading the author's head.

## Decisions

- **Name:** cookwright. No alias.
- **License:** MIT.
- **Levels:** 0 = hooks, state homes, backlog, changelog, doctor, setup. 1 = screenshot atlas, SQL test suites. 2 = secrets backends, Supabase ops pack, OTA preflight, bundle runner.
- **v1 scope:** Level 0 plus doctor plus setup stable. Levels 1 and 2 installable, flagged experimental.
- **Secrets:** never a plaintext env file, not even as a fallback. A secret is injected into one child process with target proof. Backends at launch: 1Password `op run`, macOS Keychain, `age` with a passphrase-protected identity as the free universal path (OS keystores as a doctor-suggested upgrade). No backend configured means Level 2 is off.
- **Hosts:** one adapter per agent host (manifest location, skill path, hook mechanism, subprocess invocation). Claude Code and Codex at launch; others as later adapter files. Rules live in `AGENTS.md`, skills in the open `SKILL.md` format.
- **Layout:** one monorepo: the npm package, the host adapters, the docs. One version number.
- **Test bed:** the author's private personal app. Harness CI runs against a fixture generated by `create-expo-app` plus a small committed overlay. No public example app at launch.
- **Leeka:** migrates onto the package after v1 proves on the personal app, as its own bundle. Until then Leeka keeps its own scripts and is read-only reference material.
- **Telemetry:** none at launch.

## How it gets built

Bootstrapping like a compiler. Stage 0 copies Leeka's bundle runner verbatim and, by hand in one session, makes it run on a directory that is not Leeka. From stage 1 on, every piece of cookwright (doctor, init, hooks, secrets, atlas) is built as a bundle through cookwright's own runner, so every improvement to the process is itself shipped product.

## Amendments

- 2026-10-15. Rules live in one AGENTS.md. init writes no CLAUDE.md, except one that imports AGENTS.md (the single line @AGENTS.md) when Claude Code would otherwise not read AGENTS.md: a CLAUDE.md, .claude/CLAUDE.md or CLAUDE.local.md in or above the repo shadows it, or the installed Claude Code is older than 2.1.281. An existing root CLAUDE.md gets the import line prepended instead. Decided after verifying the Claude Code docs (AGENTS.md read natively since 2.1.277, all providers since 2.1.281).
- 2026-10-15. Judgment rules, the section below: nine rules every disposition of a finding or an open question is made by, and that the orchestrator cites by number.
- 2026-10-23. Stack packs carry standards, not only tools. A pack ships each engineering rule as a pair, the sentence in a managed section of AGENTS.md and the check that measures it (a lint rule, a doc-sync rule, a doctor or gate check); a rule with no measurement is listed as advisory, apart from the rest. Hooks judge the change and the gate ratchets the repo: pre-commit checks only the staged files, so an existing app is never blocked on code it did not touch, and the gate compares the repo's violation count against the base branch, a rise being drift (FAIL) and a fall or a standing count a PASS with the number on the line. Packs are orthogonal to levels: a level measures how deep the harness goes, `packs` in the config declares the stack, and a pack is a directory in the package under the one version number, never a plugin API. Decided in discussion on the lab run; the first pack's standards are stage 4, secrets move to stage 5.

## Judgment rules (amendment 2026-10-15)

1. A harness problem never blocks the user's work. A missing tool, a missing package, an invalid config or a crash in cookwright is one printed line and a clean exit. Only a finding in the user's own change fails a hook.
2. Drift from the declared level is FAIL. A state the user chose (hooks managed by husky, a hand-kept changelog) is WARN with the reason. A FAIL the user cannot clear is a bug in cookwright.
3. Claim only what was measured. A line names what it tested; when the thing judged is not the thing tested, it is SKIP with the reason, never PASS with a footnote.
4. Logic lives in the package, imported, never copied. The user's repo holds shims, config and generated files, so an update changes behaviour without touching their tree.
5. Generated artifacts are never hand-maintained, and derived state is never stored. Stored copies rot.
6. A feature wanted for a second time gets built. A feature wanted once goes to the backlog with its real justification.
7. Nothing private in the repo, ever: no paths, usernames, credentials or private project data, in any commit. A leak is a history rewrite, not a note.
8. Escapes are per-check, named, and carry their reason in the commit message. `--no-verify` is the last resort and is documented as such.
9. The core package has no runtime dependency. Any dependency anywhere is asked for first.
