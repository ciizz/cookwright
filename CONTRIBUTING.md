# Contributing

This repo builds cookwright and is itself run by it. Read [CHARTER.md](CHARTER.md) first, then [AGENTS.md](AGENTS.md), which holds the rules every contributor and every agent works by.

## The root

- `CHARTER.md`: the product decisions. It changes only by a dated amendment, and its nine Judgment rules decide every finding.
- `AGENTS.md`: this repo's rules, with the managed block init writes between its markers. `CLAUDE.md` is the single line `@AGENTS.md`.
- `README.md`: the front page. `docs/guides/`: the user documentation, one guide per topic.
- `CHANGELOG.md`: generated by `npx cookwright changelog` from the release tags; never edited by hand.
- `cookwright.json`: this repo's own config: Level 0, the gate (`npm test`), the doc-sync rules.
- `packages/cookwright/`: the npm package, everything a user installs. `bin/` and `src/` are the CLI (tests beside the code, `*.test.mjs`); `schema/` the config schema; `skills/` the host-agnostic skills (`setup`, `bundle`); `hosts/` the files a host adapter ships (`claude/workflows/`); `docs/playbook.md` the bundle playbook; `src/lib/rules/agents-block.md` the managed rules block. `lifted/` holds files copied from Leeka awaiting extraction and must be empty before v1.
- `.claude/`: the pointers init writes (`skills/<name>`, `workflows/<name>.js`), symbolic links into the workspace package. Tracked; init rewrites them, never edit them by hand.
- `.githooks/`: the shims init writes; they call the package.
- `scripts/ci/fixture.sh` and `fixtures/expo-overlay/`: the harness fixture, a pinned `create-expo` scaffold with the overlay, the package installed from its tarball, then init, doctor, a commit through the hooks, changelog and migrate run against it.
- `.github/workflows/ci.yml`: `npm test` on ubuntu and macOS, Node 20 and 22, and the fixture on ubuntu.

## docs/dev

- `backlog.md`: open bugs (`B-nnn`) and enhancements (`E-nnn`), stable ids, one dated line each; closed items move to its last section.
- `closeouts/`: one past-tense file per shipped stage, what it did and why.
- `bundles/`: bundle state, written only by the runner (`npx cookwright bundle …`). Never edit it by hand.
- `stage-0-kickoff.md`: the kickoff of the hand-built stage 0.

## How work ships

Stage 0 excepted, work ships as bundles through the repo's own runner: plan mode first, a written plan, an adversarial review of the plan, implementation, review of the diff, a closeout in `docs/dev/closeouts/`. A small change can be a single session that still plans, reviews and runs the gate. A discovery outside the task's scope goes to the backlog, not into the diff.

## Developing

init has been run on this repo, so its git hooks are live: every commit runs the secret scan and two doc-sync rules (the bundle CLI and workflow need `packages/cookwright/docs/playbook.md` or the bundle skill staged; the setup skill and the managed rules block need a guide under `docs/guides/` staged), and every push runs `npm test` and the changelog check.

```bash
npm ci && npm test
npx cookwright doctor
npx cookwright bundle status
bash scripts/ci/fixture.sh
```

## Before you open a pull request

- Nothing private, ever: no local paths, usernames, credentials or private project data, in any commit.
- Ask before adding a dependency; the core package has none at runtime.
- Commit subjects are conventional (`feat:`, `fix:`, `perf:`, `docs:`, `chore:`, …): they are what the changelog lists.
- A change with doc implications updates the doc in the same commit.
