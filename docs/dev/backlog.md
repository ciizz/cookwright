# Backlog

Bugs are `B-nnn`, enhancements `E-nnn`; ids are stable and never reused. One line per item, dated when opened; a closed item moves to the last section with the bundle or stage that closed it.

## Open bugs

- **B-002** (2026-10-15) The SessionStart hook command looks for `node_modules/cookwright` in `CLAUDE_PROJECT_DIR`. When a Claude session starts in a subdirectory of the repo, or the package is installed in a workspace sub-package, the hook prints "package not installed", although doctor run from there would find the root. The git hook shims (stage-2) share the bug: they look for `node_modules/cookwright` in the config root (the directory holding `cookwright.json`, entered from the work tree's top since B-007's fix), so a workspace sub-package install, or a linked worktree without `node_modules`, prints the not-installed line and the hook checks nothing. Stage 3's skill and workflow pointers handle a package hoisted to the top for a nested config root (they link into the top's `node_modules`); the hook commands and the shims do not (E-034). Stage 3's Codex hook (`.codex/hooks.json`) has the same limit: it enters the work tree's top, so for a config root below it the hook prints the not-installed line, or doctor's no-config refusal when the package is hoisted; doctor's Codex `host.hook` reads that case as WARN rather than PASS.
- **B-003** (2026-10-15) The bundle CLI ignores unknown flags on every subcommand but the three `phase` verbs, so a mistyped or dropped flag passes silently. `init` and `doctor` refuse them through `onlyFlags` in `src/lib/cli.mjs`.
- **B-008** (2026-10-15) Windows: `hasTool` in `src/lib/probes.mjs` looks for the bare executable name on PATH and ignores `PATHEXT`, so `gitleaks.exe`, `node.exe` and `npm.cmd` read as absent: doctor reports gitleaks missing, the pre-commit scan skips, the gate may skip every check. Found by review:whole of stage-2; not measurable here (no Windows), to be fixed with a Windows runner (E-014).
- **B-009** (2026-10-15) Windows: the `.githooks/` shims are committed with no line-ending protection; a checkout with `core.autocrlf=true` rewrites them CRLF, `sh` fails on `}\r` and git aborts the commit (a harness problem blocking the user, against judgment rule 1), while doctor reads the file as foreign. Fix: init writes a `.gitattributes` line `.githooks/* text eol=lf` and doctor compares the shim LF-normalised (ours but broken: FAIL, run init). Found by review:whole of stage-2; not measurable here.
- **B-010** (2026-10-16) A non-Windows filesystem that refuses symbolic links (exFAT, some network mounts): init reports each refused pointer and goes on, and doctor then FAILs `host.pointers` with no way for the user to clear it, a bug by judgment rule 2. To be fixed with a durable marker of the refusal or a pointer form that is not a link.
- **B-011** (2026-10-22) init creates `.gitignore` without `node_modules` when the repo has none, so `git add -A` after init commits the installed package. Found on a bare lab repo (`git init`, `npm install --save-dev cookwright`, `npx cookwright init`, `git add -A && git commit`): 86 files committed, `node_modules/cookwright` among them, and the pre-commit secret scan read 365 KB of the package's own source. `src/lib/init/gitignore.mjs` asks git only whether the env files are ignored (`PROTECTED`); a scaffold's `.gitignore` covers `node_modules`, a bare repo's does not exist. The README's "commit the files init names, by path" is not a defence, since `git add -A` is what a newcomer types. Fix, decided 2026-10-23: both. init asks git about `node_modules` the same way and writes or appends the line; a doctor check reads a tracked `node_modules` as FAIL with the untrack command as its next step (rule 2: drift). Found by the developer's own first run, not by a stage.
- **B-012** (2026-10-23) `gate.scripts` reads PASS when `gate.checks` is empty, so a fresh Expo app (no test script) reaches 17 PASS with a pre-push that runs nothing, and only the setup skill's end pass, which an all-PASS readout gives no reason to run, offers a check. Decided 2026-10-23: WARN, "no gate checks configured; pre-push runs nothing", with adding a check to `gate.checks` as the next step (rule 2: the developer did not choose this state, init did). The getting-started guide shows `gate: npm test`, which a fresh Expo app never produces, and never says how to write `gate.checks` by hand; both change with this (rule 3). Found on the developer's lab run.
- **B-013** (2026-10-23) The doctor summary reads `level 0 declared: complete; unverified: tools.gitleaks` when a check could not measure, so a session-start readout says "complete" on a repo whose secret scan does not run. Decided 2026-10-23: "complete" only when every check of the level measured; otherwise the summary leads with the unverified checks and what makes them measurable (rule 3). Measured on the lab with gitleaks and claude hidden from PATH: both read SKIP and the summary still said complete.

- **B-015** (2026-10-25, closed the same day in stage-4) vitest exits 1 on a green suite under load: `[vitest-worker]: Timeout calling "onTaskUpdate"`, 478 of 478 passed, and the stage-4 baseline gates 0 and 1 were recorded red on it. Mechanism, read in vitest 3.2.7: a worker reports each test to the main process over birpc with a 60 s timer the forks pool does not make configurable; the tests are synchronous (`spawnSync`, sync fs) and between tests the runner awaits only microtasks, so a file never reaches the event loop's poll phase until it ends; when a file runs past 60 s under load (load average 10 to 18 with other sessions on the machine), Node fires the due timer before it reads the reply that already arrived, once per such file (two errors, two files). A harness problem blocking the bundle, rule 1; a different mechanism from B-014, whose fix held. A first attempt, `maxWorkers` at half the cores (commit 7adc312), was measured green once and red once at load 10 and is reverted. Closed: `afterEach(() => new Promise((resolve) => setImmediate(resolve)))` in `vitest.setup.mjs`, one yield per test so every reply is read while its timer is live; measured twice after the change at load averages 11 and 17: 478 of 478, exit 0, 66 s and 61 s.
