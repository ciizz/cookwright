## Open bugs

- **B-002** (2026-10-15) The SessionStart hook command looks for `node_modules/cookwright` in `CLAUDE_PROJECT_DIR`. When a Claude session starts in a subdirectory of the repo, or the package is installed in a workspace sub-package, the hook prints "package not installed", although doctor run from there would find the root. The git hook shims (stage-2) share the bug: they look for `node_modules/cookwright` in the config root (the directory holding `cookwright.json`, entered from the work tree's top since B-007's fix), so a workspace sub-package install, or a linked worktree without `node_modules`, prints the not-installed line and the hook checks nothing. Stage 3's skill and workflow pointers handle a package hoisted to the top for a nested config root (they link into the top's `node_modules`); the hook commands and the shims do not (E-034). Stage 3's Codex hook (`.codex/hooks.json`) has the same limit: it enters the work tree's top, so for a config root below it the hook prints the not-installed line, or doctor's no-config refusal when the package is hoisted; doctor's Codex `host.hook` reads that case as WARN rather than PASS.
- **B-003** (2026-10-15) The bundle CLI ignores unknown flags on every subcommand but the three `phase` verbs, so a mistyped or dropped flag passes silently. `init` and `doctor` refuse them through `onlyFlags` in `src/lib/cli.mjs`.
- **B-008** (2026-10-15) Windows: `hasTool` in `src/lib/probes.mjs` looks for the bare executable name on PATH and ignores `PATHEXT`, so `gitleaks.exe`, `node.exe` and `npm.cmd` read as absent: doctor reports gitleaks missing, the pre-commit scan skips, the gate may skip every check. Found by review:whole of stage-2; not measurable here (no Windows), to be fixed with a Windows runner (E-014).
- **B-009** (2026-10-15) Windows: the `.githooks/` shims are committed with no line-ending protection; a checkout with `core.autocrlf=true` rewrites them CRLF, `sh` fails on `}\r` and git aborts the commit (a harness problem blocking the user, against judgment rule 1), while doctor reads the file as foreign. Fix: init writes a `.gitattributes` line `.githooks/* text eol=lf` and doctor compares the shim LF-normalised (ours but broken: FAIL, run init). Found by review:whole of stage-2; not measurable here.
- **B-010** (2026-10-16) A non-Windows filesystem that refuses symbolic links (exFAT, some network mounts): init reports each refused pointer and goes on, and doctor then FAILs `host.pointers` with no way for the user to clear it, a bug by judgment rule 2. To be fixed with a durable marker of the refusal or a pointer form that is not a link.
- **B-016** (2026-10-25, open: cause unknown, the proposed guard not built) This checkout's `.git/config` carried `core.hooksPath = .husky/_` (file modified 2026-10-25 18:05, before stage 4's session; no `.husky` directory exists), so git ran no cookwright hook on this bundle's first 41 commits while the implementer sessions reported the hooks as passing (an inference, not an observation). Found by implement:s4 of stage-4; restored to `.githooks` by hand, and the secrets scan and both doc-sync rules re-measured over the range: clean. Cause unknown. `.husky/_` is the value the test suite uses for a foreign hooks setup (`doctor.test.mjs`, `init.test.mjs`); the pre-push gate strips git's repository variables (`GIT_LOCAL_ENV`), so a hook-run suite is not the writer; a test helper calling `run(repo.root, 'git', ['config', '--local', …])` with an undefined root would run in the process cwd, this repo. Proposed: `run` in `test-helpers.mjs` refuses a cwd outside the scratch root, and the implementer role checks `git config core.hooksPath` before claiming a hook ran.
- **B-017** (2026-10-26) `npx cookwright bundle record <slug> qa` stores whatever stdin holds, an empty stdin included: `bundle record stage-4 qa --help` stored a one-byte `qa/round-3.md` and pushed it to `qaRounds` (the flag is ignored, no usage is printed), and the CLI has no way to retract a round, so the only recovery was discarding the uncommitted state with git and redoing the CLI calls (stage-4 QA run 7). Proposed: `record` refuses an empty or whitespace-only stdin and any unknown flag with its usage line, and a round or findings record can be retracted while uncommitted.
- **B-019** (2026-10-26) `bundle record <slug> findings <phase>` on a re-check (`recheckOf`) carries round-1 issues forward as still open when the re-check's issue carries a different `file`: `carryForward` keys an issue on `file::location::problem`, and the verifier re-filed five red-team findings under the plan's path (`docs/dev/bundles/b-018/plan.md`) where round 1 had the code paths (`packs/expo/eslint.cjs`, `eslint.test.mjs`, `fixture.sh`, `README.md`, `packs/supabase/eslint.cjs`), with location and problem equal. The record then held 13 issues, the five originals `plausible`, and `phase done plan-review` refused on a P2 that the same record shows resolved (b-018 plan-review run 2). Seen again 2026-10-27 (stage-5 plan-review re-check 2): the verifier kept `file` and `location` but paraphrased one word of `problem` ("repo" for "repository") and dropped `index`, so a finding its evidence rejected was stored `not re-judged` and `phase done` needed `--accept-open`. The `index` route needs the re-check schema to require it.
- **B-020** (2026-10-26) The closeout's `Output tokens` number overstates when a bundle runs inside a long session: `phase done --usage N` takes the Workflow result's `usage`, which is the turn's `budget.spent()`, a counter cumulative over the session, so each run's reading includes every earlier turn (b-018's six runs read 1.86M to 1.94M each, 9.5M summed, against 0.97M of subagent tokens the runtime reported per run). - **B-022** (2026-10-27) The bundle record scrubber (`src/lib/bundle/scrub.mjs`) redacts a machine-local path only from a known start (this machine's home or temp directory spelled whole, `/tmp`, `/Users/<name>`, `/Volumes/<name>`, a Windows drive or share), so a fragment that names only the head of the temp directory (`/var/folders`, then an elided middle and a run's `mkdtemp` suffix) reaches a committed session report unredacted (stage-5 implement:s2's report; review:engine). Not machine-identifying (no user segment), but against the no-local-paths rule. Proposed: treat `/var/folders/` and `/private/var/folders/` as machine-local starts, and a `mkdtemp`-shaped name under any temp start.
