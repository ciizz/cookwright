# Stage 1 — doctor and init (Level 0)

Written 2026-10-15; revised the same day after an adversarial read (two P1s, six P2s folded in), approved by the developer with three amendments (§7 moves this repo's rules to AGENTS.md first; an unknown host is a config FAIL; test counts are measured, never carried), then revised again after plan-review round 1 through the runner (31 findings; every P1 and P2 folded in below, two of them as developer decisions in §2). The first bundle through cookwright's own runner. Sections are numbered so the split can name them (`plan §4.4`).

## 1. Context

The charter's first two properties are guided setup and graceful degradation, and its third is that the harness knows its own level and detects drift. Stage 0 made the bundle runner run here; nothing a user could install exists yet. Stage 1 builds the two commands every later level hangs off: `init`, which takes a repo to Level 0, and `doctor`, which checks at every session start that Level 0 is still there and reports what is missing, never failing a hook.

What Leeka offers for this (read 2026-10-15, read-only): no agent-host hooks, no doctor, no setup script. Its Level-0 material is the state-homes vocabulary and rules in its rules file ("Ledger discipline", "Backlog discipline", "Conventions"), the backlog format, a tag-driven changelog generator, husky git hooks (secret scan, doc-sync rules, tests on push) and a manual guardrail canary whose `PASS/FAIL/WARN/SKIP` readout is the shape doctor adopts. The rules and the readout shape are extracted here; the git hooks and the changelog generator are deferred (decided by the developer, 2026-10-15).

## 4. Design

### 4.1 The `cookwright` bin

`packages/cookwright/bin/cookwright.mjs`, `#!/usr/bin/env node`, **with no entry guard**: it is `process.exitCode = await dispatch(process.argv.slice(2))` and nothing else. The guard `bundle.mjs` uses (`import.meta.url === pathToFileURL(process.argv[1]).href`) is false through a symlink, and the bin is always reached through one (`node_modules/.bin/cookwright`, and here `node_modules/cookwright` → `packages/cookwright`). The dispatcher lives in `src/cli-main.mjs`, `dispatch(argv, io)`: `init` → `src/init.mjs`, `doctor` → `src/doctor.mjs`, `bundle` → `main()` of `src/bundle.mjs` with the remaining argv (so `cookwright bundle` with nothing after it prints the bundle usage). Anything else prints the usage and exits 2. Each subcommand's `main(argv, { cwd, input })` returns the exit code, as `bundle.mjs` does today, so tests call it in process; one test spawns the bin through a symlinked path.

`package.json` gains `"bin": { "cookwright": "bin/cookwright.mjs" }`; `files` becomes `["bin", "src", "schema", "!src/**/*.test.mjs", "!src/test-helpers.mjs"]`. The workspace entry in `package-lock.json` records `bin`, so s1 runs `npm install` once, commits the lock with the change, and verifies that a clean `npm ci` leaves the tree clean and creates `node_modules/.bin/cookwright`. If the link does not appear, the root `package.json` gets a `cookwright` script instead and the invocation below follows.

**The invocation** printed by every next-action line and every doc is `npx cookwright` (§2 (b): the developer reserves the npm name before s1's docs land). `CLI = 'npx cookwright'` and `BUNDLE_CLI = 'npx cookwright bundle'` are the constants; nothing else spells it.

**The runner's transcript path** (§2 (a), s1): `setRunId` in `src/lib/bundle/phases.mjs` stores `runId` only; `phase run` and `phase done` lose `--transcript-dir` (an unknown flag is a refusal, as today); any renderer that printed the directory (`status`, the closeout draft) prints the run id instead; `state.test`/`bundle.test` gain a test that walks a saved state and refuses any string starting with `/`. The playbook's loop step 2 and the skill's resume step drop the flag. Note for the orchestrator: `cli` is a field of the Workflow args (`phases.mjs`, consumed by `bundle-phase.js`), so once s1 lands, a run of this very bundle that was in flight before it cannot resume from cache; new runs recompute their args and are unaffected.

Shared CLI pieces move out of `bundle.mjs` into `src/lib/cli.mjs`: `parseArgv`, `Refusal`, `need`, `stringFlag`, `numberFlag`; their refusal texts (`missing <what>`, `--x must be a number`) move to `src/lib/messages.mjs`. `bundle.mjs` imports them and keeps re-exporting `parseArgv` and `Refusal` for its tests.

Strings: `src/lib/messages.mjs` is the home for the bin's, init's, doctor's and `cli.mjs`'s strings and for `CLI`; s1 creates it with the bin's and `cli.mjs`'s strings and `CLI`, and each later session adds its own. It may import `CONFIG_FILE` from `config.mjs`; **`config.mjs` never imports `messages.mjs`** (the loader's messages stay in `config.mjs`, as today), and `hosts.mjs` imports neither, so no cycle can form. `src/lib/bundle/messages.mjs` keeps the bundle strings and imports `CLI` to build `BUNDLE_CLI`. Every place that prints or documents the old invocation changes: `src/lib/bundle/messages.mjs`, the usage header of `bundle.mjs`, `hosts/claude/skills/bundle/SKILL.md`, `docs/playbook.md`, `README.md`, E-007's text in the backlog. The stage-0 closeout and kickoff are history and keep the old string.

### 4.2 Config: `level`, `paths.changelog`, a bounded root, the unknown-host text

`src/lib/config.mjs`: `level` joins `KNOWN_KEYS.top`, `DEFAULTS.level = 0`, validated as one of `KNOWN_LEVELS` (§4.3), an integer; `paths.changelog` joins `KNOWN_KEYS.paths` with default `CHANGELOG.md` and the same root-relative rule as the other paths (not part of the nesting check, and not a non-code pathspec: a changelog line is a code change). The schema twin gains both; the parity test in `config.test.mjs` holds them to the validator, the level enum to `KNOWN_LEVELS`.

**A bounded root.** `findRoot(cwd, { stopAt })` never climbs past `stopAt`; `openRepo` (and init's and doctor's root lookup) pass the git toplevel of `cwd` when inside a work tree, so a `cookwright.json` in an enclosing directory or an enclosing repo is never picked up. Outside a work tree the walk is unchanged. Test: a nested repo under a directory holding a `cookwright.json` is refused with `noConfig`.

**The unknown-host text.** The loader's message for a host with no entry in the host table becomes `hosts: host "<x>" is not available in this version of cookwright (known: claude)`; it lives in `config.mjs` with the loader's other messages (§4.1's import rule). doctor's `config` check shows it verbatim (§4.8).

### 4.3 Levels: `src/lib/levels.mjs`

The ladder, in one place: `LEVELS = { 0: { name, summary, requires: [doctor check names] } }`, `KNOWN_LEVELS`, `nextLevel(level)` (null in this version; the message says Level 1 is not available in this version of cookwright). `requires` is what doctor measures the declared level against: **a required check that is FAIL is drift**; a WARN is reported as weak; a SKIP is reported as unverified; neither counts as drift, so a working but imperfect setup reads as complete, and the level line always names what is weak or unverified. Every state in which Level 0 is silently off is a FAIL in §4.8 (a missing home, a missing, stale or malformed block, rules that Claude ignores, no hook). Level 0 requires: `config`, `git`, `homes.backlog`, `homes.closeouts`, `homes.changelog`, `rules.block`, `host.rules`, `host.hook`. A test holds every name in `requires` to doctor's check registry.

### 4.4 init

`npx cookwright init [--base <branch>] [--dry-run]` (spelled with the §2 (b) invocation). It refuses unknown positionals and flags with the usage, exit 2, and names `bundle init` in the refusal when `--plan` or `--split` is present. Non-interactive and idempotent: every step reports `wrote`, `updated`, `kept` (present, left alone) or `skipped` (nothing needed, with the reason), and **a second run changes no byte and reports no `wrote` or `updated` row**. `--dry-run` prints the same report, writes nothing and skips the doctor step, saying so. It never deletes or overwrites user content.

**Preflight before any write.** init first reads every target it may touch (`cookwright.json`, `AGENTS.md` and its block state, `.claude/settings.json`, `CLAUDE.md`, `.gitignore`) and computes every row; a refusal (invalid config, malformed block, unparseable settings, a git probe that errors) exits 2 **before any write**, with no doctor run, so a refused tree is untouched as a whole, not only the file that refused. Only then are the rows applied, in order.

Root: the directory holding `cookwright.json` found upward from cwd, bounded by the work tree (§4.2), else `git rev-parse --show-toplevel`. Not a git work tree: refused, exit 2. init works from a subdirectory and keeps the invocation cwd for the host scan of step 4.

Steps, in order (library under `src/lib/init/`, one function per step, each `(repo, io) → row`):

1. **`cookwright.json`:** absent → write `{ $schema: "./node_modules/cookwright/schema/cookwright.schema.json", version: 1, level: 0, hosts: ["claude"], baseBranch, paths (every key, explicit defaults), gate: { checks } }`. `baseBranch` is `--base`, else an existing `main`, else an existing `master`, else the checked-out branch (`git symbolic-ref --short HEAD`, which works on an unborn HEAD), else `main`. `gate.checks` is `[{ name: "test", run: "npm test" }]` when `package.json` defines `test`, it is not npm's `no test specified` placeholder, and it is not a watch-mode script (`--watch`, `--watchAll`, which never exits); else `[]`, with the reason in the row. Present → load (a refusal if invalid) and `kept`; init never edits an existing config.
2. **State homes:** `paths.backlog` from the template (§4.6) when absent, creating its directory; `paths.closeouts` created with a `.gitkeep` when absent, and `.gitkeep` added (`updated`) when the directory exists but is empty with no tracked content (git keeps no empty directory, so a clone would lose it); `paths.changelog` from the template when absent. Present → `kept`.
3. **Rules block** (§4.5): by `blockState`: `absent` with no `AGENTS.md` → written with the block; `absent` in an existing file → block appended after one blank line (a file without a trailing newline gets one first); `stale` → block replaced between the markers, everything outside byte-identical (`updated`); `current` → `kept`; `newer` → `kept` with a note (update cookwright); `malformed` → refused in preflight.
4. **Host rules import** (claude): the scan runs from the invocation cwd upward, through the root and its ancestors, for `CLAUDE.md`, `.claude/CLAUDE.md` and `CLAUDE.local.md`. If `CLAUDE.md` exists at the root → ensure an import line (prepend `@AGENTS.md` as the first line when none is present, `updated`); else if the scan finds any shadowing file, **or the `claudeVersion` probe reports Claude Code older than 2.1.281** (which reads only `CLAUDE.md`) → write `CLAUDE.md` containing `@AGENTS.md` (`wrote`); else `skipped` with the reason (AGENTS.md is read natively; or claude not on PATH, so nothing shadows and nothing is known to need the import). "Present" for the import means the token `@AGENTS.md` on a line outside a fenced block and outside backticks; a mention in prose code is not an import (Claude skips imports in code spans).
5. **Host hook** (claude): `.claude/settings.json` absent → written with the hook; present → parsed, then: a `SessionStart` command **equal to `HOOK_COMMAND`** → `kept`; equal to an entry of `HOOK_COMMANDS_PAST` (earlier versions of the command, listed in `hosts.mjs`, empty today) → replaced by the current one (`updated`); otherwise the entry is appended, everything else preserved (other groups, other matchers, other keys), written back with the file's own indent (two spaces when new), `updated`; unparseable → refused in preflight. Detection is never a substring search: an `echo "run cookwright doctor"` is not a hook. The entry has no `matcher`, deliberately: doctor runs on startup, resume, clear and compact. It carries `"timeout": 10`. The command is one constant, `HOOK_COMMAND`, defined in `src/lib/hosts.mjs` next to the claude entry **together with its three fallback lines** (`hosts.mjs` imports nothing from `messages.mjs` or `config.mjs`, which would close a module cycle: `config` → `hosts` → `messages` → `config`). One shell line, in three steps, so each absence reads as itself:

   ```sh
   cd "${CLAUDE_PROJECT_DIR:-.}"; command -v node >/dev/null 2>&1 || { echo "cookwright doctor skipped, needs node, run setup"; exit 0; }; [ -f node_modules/cookwright/bin/cookwright.mjs ] || { echo "cookwright doctor skipped: package not installed (npm install)"; exit 0; }; node node_modules/cookwright/bin/cookwright.mjs doctor --hook || echo "cookwright doctor crashed (exit $?)"
   ```

   No `npx`: `npx --no-install` is deprecated and contacts the registry before refusing (measured: a 404 round trip in a repo without the package), and it adds most of a second of startup. A direct `node` call is about 60 ms, needs no network, and every branch ends at exit 0. Hooks run through `sh -c` with `CLAUDE_PROJECT_DIR` exported, which is Claude's cwd; the `cd` pins the hook to it, and doctor's root lookup climbs from there (§4.2).
6. **`.gitignore`:** ensure `.env` and `.env.local` are each ignored, probing **one path per call** (`git check-ignore -q <path>`: exit 0 ignored, 1 not, anything else a refusal with git's stderr; `-q` with two paths is fatal, and without `-q` git exits 0 when only one is ignored, measured 2026-10-15); the probe is one shared function, `ignored(path)` in `src/lib/probes.mjs`, used by doctor's `secrets.env` too. When either is not ignored, append `.env`, `.env.*` and `!.env.example` (`updated`; a file without a trailing newline gets one first); absent file → `wrote`.
7. **Doctor:** run §4.8 and print its full readout. init's exit code is doctor's.

No stack detection in this stage: init is the same on an Expo app and on this repo.

### 4.5 The managed rules block

Template `packages/cookwright/src/lib/rules/agents-block.md`, rendered with the config's paths (`{{paths.backlog}}` and the like); `RULES_VERSION = 1`. Markers: `<!-- cookwright:begin rules v1 -->` and `<!-- cookwright:end -->`. The block opens by saying it is managed, that edits inside the markers are lost on refresh, and that the user's rules go outside.

Why a block in the repo rather than an import of a file under `node_modules`: `AGENTS.md` has no import syntax, other hosts read it plainly, and the rules must exist before `npm install` has run. The block's version, refreshed by init against the package's render, is how "updates reach users" for text.

**One definition of "current":** `blockState(text, rendered) → { state: absent | current | stale | newer | malformed, …}` in `src/lib/rules/block.mjs`, used by init step 3 and doctor's `rules.block`. Line endings are normalised to LF before comparing; the block is written with the file's dominant line ending, so a CRLF file stays CRLF and a second run is `kept`. `stale` = the begin marker's version is older than `RULES_VERSION`, or the content between the markers differs from the render; `newer` = the marker's version is above the package's (update cookwright); `malformed` = a begin marker without an end, or two begin markers; refused, never rewritten. A second end marker after the first is user text and is left alone.

Content (prose written in s3, from Leeka's generic sections, with nothing of Leeka's in it), about 50 lines:

- **State homes.** Every kind of state has exactly one home; the rules file is the map, not the store. Tasks, bugs and enhancements → the backlog. Feature narratives → a closeout, written once, past tense, at close. User-visible changes → the changelog's Unreleased section. Don't record what is derivable (merge state is git, test state is the suite). No "pending" or "next" narrative in an active doc: a thing to do is a backlog entry. The agent updates the state homes at every status change it takes part in or learns of.
- **Backlog discipline.** An out-of-scope discovery is logged, not fixed: a bug → Open bugs with a `B-nnn` id, an enhancement → Open enhancements with `E-nnn`; ids are stable and never reused. The bar: touching files outside the declared surface, or more than about five lines outside scope. Plan-mode discoveries count. Closing moves the line to Closed with a one-line note; a commit that fixes an item names the id.
- **Doc sync.** A change with doc implications updates the doc in the same commit; when unsure, update.
- **Session start.** `cookwright doctor` runs at session start and its readout is in context; a FAIL is dealt with before other work, a WARN names the next step.
- **Secrets.** Never write a plaintext env file; never put a secret value in a doc, a commit, or a transcript.
- **Conventions.** Ask before adding a dependency. Re-read the rules file when it changes mid-session. Retrospectives go in closeouts, not in the rules file.

### 4.6 State-home templates

`src/lib/templates/backlog.md`: the title, a short "How to use" (the id scheme, the log-instead-of-fix bar, close by moving the line), then `## Open bugs`, `## Open enhancements`, `## Closed`, one line per item, the compact form this repo's own backlog uses. `src/lib/templates/CHANGELOG.md`: a title, one line saying it is hand-maintained (the generator is a later bundle), `## Unreleased`. The templates and the rules block are content seeded once and owned by the user afterwards (init keeps them); nothing init writes is a script.

### 4.7 Host wiring

The claude entry in `src/lib/hosts.mjs` gains `settings: '.claude/settings.json'`, `HOOK_COMMAND` with its three fallback lines, `HOOK_COMMANDS_PAST` (empty), `hookTimeout: 10`, `importLine: '@AGENTS.md'`, the three shadowing file names (`CLAUDE.md`, `.claude/CLAUDE.md`, `CLAUDE.local.md`) and `agentsNativeSince: '2.1.281'`. init and doctor read the host table; nothing about Claude Code is hardcoded elsewhere. ### 4.8 doctor

`npx cookwright doctor [--hook]` (spelled with the §2 (b) invocation). Library under `src/lib/doctor/`: one function per check, `(repo, probes) → { status, note }`, registered by name in one table; the verdict constants are shared with the landing check (`PASS`, `FAIL`, `WARN`, `SKIP` and `summarize` move from `src/lib/bundle/check.mjs` to `src/lib/verdict.mjs`; `check.mjs` imports and re-exports them, so `bundle.mjs` and `bundle.test.mjs` keep their imports). Probes (`hasTool`, `claudeVersion`, `ignored`) are injected so tests need no Claude binary. No network, no npm, no stdin read, no recursive directory walk; budget under two seconds, and every subprocess timeout fits inside it: `claude --version` is spawned only when its answer matters (see `host.rules`), with a 1.5 s timeout; a failure or timeout is "version unverified" and reads as not on PATH. doctor refuses unknown positionals and flags (exit 2).

**When the config does not load** (`config` FAIL, the loader's message verbatim, the unknown-host text included): every check that needs the config (`homes.*`, `backlog.ids`, `rules.block`, `host.*`) is SKIP with the note `config invalid`, the config-free checks (`git`, `rules.size`, `secrets.env`) still run, the level line reads `level unknown: config invalid`, exit 1. **When git is absent** (`hasTool('git')` false): every git-dependent check is SKIP with the mandated `skipped, needs git, run setup`.

|---|---|---|---|---|

| `homes.backlog` | file with the three section headings | headings missing | file missing | config invalid |
| `homes.closeouts` | directory exists | | missing | config invalid |
| `homes.changelog` | file exists | | missing | config invalid |

| `rules.block` | `current` | `newer` (update cookwright) | no `AGENTS.md`, `absent`, `stale` (run init), `malformed` (the path): in each, Level 0's rules are not what the package ships | config invalid |

| `secrets.env` | no tracked `.env` or `.env.*` anywhere in the index, none untracked at the root, and `.env` and `.env.local` each ignored | an untracked `.env` / `.env.*` at the root (a plaintext env file; Level 2 replaces it), or `.env` or `.env.local` not ignored | a tracked `.env` or `.env.*` at any depth (named) | needs git |

`secrets.env` matches exactly `.env` and `.env.*` (the same patterns init writes to `.gitignore`; `.envrc` is not matched), exempts `.env.example`, `.env.sample` and `.env.template` at any depth, finds tracked files repo-wide through the index (`git ls-files -- .env '*/.env' '.env.*' '*/.env.*'`, names only, cheap at any repo size) and untracked ones at the root only (never a walk, never `node_modules`), decides "ignored" with the shared `ignored(path)` probe, one path per call, and only lists names: it never opens an env file, so no value can reach the readout. Its notes never claim "no plaintext secret anywhere".

Output, by hand: one line per check, `STATUS  name  note`, then `N checks — a PASS, b FAIL, c WARN, d SKIP`, then the level line: `level 0 declared: complete` or `level 0 declared: drift, k piece(s) missing: …` (FAILs among `requires`), followed by `weak: …` naming any WARN among `requires` and `unverified: …` naming any SKIP among `requires`; `level unknown: config invalid` when the config did not load; then `next: <nextLevel message>`. Exit 0, 1 on any FAIL, 2 when refused (no `cookwright.json`: the note says `run <CLI> init`).

`--hook`: the same checks; prints only the non-PASS lines, the summary and the level line (one line, `cookwright doctor: level 0 complete`, when everything passes, so the session knows it ran); always exits 0: on FAIL, on a thrown probe (printed as one line), and with no `cookwright.json` (prints the `run <CLI> init` line). Everything goes to stdout, which a SessionStart hook adds to the session's context; stderr is not shown to the agent.
