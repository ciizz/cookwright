## 1. Context

Level 0 is "hooks, state homes, backlog, changelog, doctor, setup" (charter). Stage 1 shipped init, doctor and the state homes; two Level 0 pieces were deferred to this stage: the git hooks (E-010: a secret scan that skips when its tool is absent, tests on push, the doc-sync rule mechanism) and the changelog generator (E-011: tag-driven, `--check`, `--unreleased`). Until now the rules block says "User-visible changes: the Unreleased section of CHANGELOG.md", hand-maintained, and the doc-sync rule is prose with nothing enforcing it.

What Leeka offers (read 2026-10-15, read-only): three husky v9 hooks. `pre-commit` runs lint-staged, a gitleaks scan of the staged diff (absent binary warns and continues; "a failure to run is not a finding"), `tsc`, and six doc-sync rules, each a path→doc map over the staged file list (`git diff --cached --name-only --no-renames --diff-filter=ACMRD`), all evaluated before one exit so a commit shows every failure at once. `pre-push` runs the unit suite ("pre-push, not pre-commit, so it stays cheap enough not to be bypassed"). `post-merge` prints a reminder. `scripts/generate-changelog.mjs` derives `CHANGELOG.md` from the commit ranges between semver release tags (`--merged HEAD`), reads release metadata from the annotated tag body, classifies conventional commit subjects into sections, stores no Unreleased section ("it would churn on every commit and rot between releases, which is precisely how the old one died"), and `--check` fails on any byte of drift. Its recorded gap: `--no-verify` skips the doc-sync rules and the secret scan together, so a Rule-only deferral was wanted (Leeka's E-218).

Extracted here: the staged-diff gitleaks scan with its exit-code discipline, the doc-sync mechanism as config, tests on push through the existing gate checks, the generator's model. Left in Leeka: lint-staged and tsc (the user's stack), the six rules' content, the content-based migration tripwires (a stack pack's), the `copy`/`polish`/`harden` types and the merge-subject highlights, the ios/android/store tag fields as special cases (they render through the generic `key: value` rule below), prettier formatting (a dependency).

## 2. Decisions (the developer, 2026-10-15)

- **Hook install:** tracked `.githooks/` shims plus `core.hooksPath`. "Two conditions: when node or the package is missing, the shim prints one line and exits 0, never blocking the commit, same contract as the SessionStart hook. A repo with a foreign hooksPath (husky, lefthook) is reported by doctor as hooks absent with the reason; log as a backlog enhancement that init could append the shim call into those hooks instead of stopping."
- **Changelog:** generated only, no stored Unreleased. "One requirement: a repo with no release tag yet must pass `--check` (an empty generated changelog is byte-stable), with a test, since every user's repo starts there. Drop this repo's hand-written Unreleased lines."
- **Doc-sync dogfood:** the bundle CLI and workflow → the playbook or the bundle skill, tests excluded by pathspec. "The rules block's doc-sync line should say that a `COOKWRIGHT_SKIP=doc-sync` commit carries the reason in its message, since the escape itself leaves no trace."

Consequences fixed by these: the managed rules block goes to **v2** (§4.7), the first real exercise of its refresh path; `CHANGELOG.md` here is regenerated and its hand-written lines drop (recoverable from the commit log; every commit in this repo is conventional, *measured*: 23 chore, 16 fix, 9 feat, 9 docs, 3 test, 1 revert, 1 refactor).

**Dispositions made in this plan**, surfaced by the review; the orchestrator records each with `bundle decide` at kickoff unless the developer amends it here:

1. **Amended by the developer:** a foreign hooks setup (`core.hooksPath` elsewhere or from a non-local origin, or user hooks in the hooks dir) is **WARN** on `hooks.path` with the reason, not FAIL. "It is a chosen state, not drift; a permanent FAIL the user cannot clear trains them to ignore doctor. FAIL stays for unset (run init) and for our shim present but broken. The two file checks SKIP as planned."
2. gitleaks absent is **SKIP** in doctor (`tools.gitleaks`, "unverified"), matching the shipped convention for a missing tool (`needsGit`, `noClaude`) and the hook's own line, not WARN.
3. `npx cookwright changelog` **refuses** to replace a changelog that is not generated unless `--adopt` is passed; this repo's dogfood passes it.
4. No config lever to turn a hook check off; the escapes are `COOKWRIGHT_SKIP` per invocation and `--no-verify`. A `hooks.disabled` list goes to the backlog, not built.
5. The names: hook checks are `secrets`, `doc-sync`, `gate`, `changelog` (what `COOKWRIGHT_SKIP` takes); the config key is `hooks.docSync`; doctor's are dotted (`hooks.path`, `tools.gitleaks`).
6. **Amended by the developer:** pre-push runs the single `gate.checks` list in this stage (*measured*: 18.3 s here today), **prints the elapsed time on the pre-push gate line**, and a backlog enhancement opens for a `hooks.push` list that overrides `gate.checks` on push, "since the bundle gate wants thorough and the push hook wants cheap enough never to be bypassed."
7. B-002 is widened to the shims rather than a new id: one bug, "the package is looked for at the work tree root".

**Dispositions after plan-review round 1** (the orchestrator, recorded with `bundle decide`):

8. The pre-push checks judge the working tree, never the pushed commit (finding 3). Refusing a push whose tree is dirty or whose pushed sha is not HEAD would breed `--no-verify`; instead each pre-push line carries `(judged on the working tree, not <sha>)` whenever that is the case, and the README says so. A per-sha temporary worktree is a later enhancement, backlogged.
9. Findings leave `cookwright hook` with **exit 10**; the shim maps 10 to 1 and everything else that is not 0 to a crashed line and exit 0 (finding 10), so a module-load failure can never block a commit. A harness problem inside one check is that check's SKIP line and never changes another check's FAIL (finding 11); `secrets` runs without a config (finding 12).
10. Linked worktrees: `core.hooksPath` is shared repo config, so a sibling worktree whose branch lacks `.githooks/` silently runs no hook (finding 4, *measured*). Accepted as a known state that doctor reports there (`hooks.pre-commit FAIL missing, run init`) and init repairs on that branch; no refusal, no worktree-scoped config in this stage.
11. `tools.gitleaks` runs one bounded dry invocation at session start so a malformed `.gitleaks.toml` is drift, not a silent skip (finding 5).
12. Release order is version order; a tag that is not an ancestor of the next version is reported by the command on stderr and rendered anyway, deterministically (finding 7).
13. A `.githooks/pre-commit` or `pre-push` that is neither ours nor calls cookwright makes the setup foreign (WARN, nothing written), whatever `core.hooksPath` says (finding 14).

## 4. Design

### 4.1 The `cookwright hook <name>` command

`npx cookwright hook pre-commit|pre-push [args…]` is what the shims call; nothing else in the hooks is script. `src/hook.mjs` exports `main(argv, io)` like init and doctor; `cli-main.mjs` gains `hook` and `changelog` (§4.4) in `COMMANDS`, and the usage line becomes `<init|doctor|changelog|hook|bundle>` (the test at `cli-main.test.mjs:38` follows). **Everything after the name is accepted and ignored**: git passes `<remote> <url>` to pre-push and the shim forwards `"$@"` (*measured*: `hook pre-push origin ../bare.git`), so a positional refusal would abort every push. Only a missing or unknown name is a refusal (usage, exit 2; the shim turns it into a crashed line). The root is the git work tree (`workTreeRoot(cwd)`), and the config is loaded from it when present: `openDoctorRepo(cwd, probes, { home })` with `probes = { ...PROBES, ...io.probes }`, as doctor does, but a missing or invalid config is not a refusal here (below). Git runs hooks from the work tree root, so the shims need no `cd`.

**The exit contract.** The command exits **10 when, and only when, a check FAILed**: a secret in the staged diff, a doc-sync rule with its doc not staged, a failing gate check, a stale changelog. The shim (§4.2) maps 10 to exit 1 for git and every other non-zero code to one crashed line and exit 0, so a failure before `main` runs (a module that does not load, a syntax error left in the working tree, an unsupported Node) can never block a commit (disposition 9). Inside the command, everything about the harness itself is a **per-check SKIP line**, never a change to the exit code of the other checks (disposition 9): a check that threw or timed out → `SKIP  <check>  could not run: <first line>`; a git error in doc-sync, or an npm script the gate cannot find → `SKIP  <check>  <reason>`; a missing or invalid `cookwright.json` → every config-dependent check (`doc-sync`, `gate`, `changelog`) is `SKIP  cookwright.json invalid: <the loader's message>; run npx cookwright doctor`, **while `secrets` still runs**, since it needs only the git root (disposition 9). doctor owns misconfiguration (§4.6 adds the checks that make that true); a hook that blocks on the harness's own state is one that gets `--no-verify`'d. Only a failure outside every check (the argv, the root lookup) is one whole-hook line, exit 0.

**Checks**, a registry like doctor's (`src/lib/hooks/registry.mjs`): `pre-commit` → `secrets`, `doc-sync`; `pre-push` → `gate`, `changelog`. Each is `(repo, io) → { status, note }` with the shared verdicts (`PASS`, `FAIL`, `SKIP`; no WARN in a hook). **Every check runs even after a failure**, so one commit shows every red at once (the gate's rule), and the exit code is 10 whenever any line is FAIL. Output: one line per check, `<hook>  <STATUS>  <check>  <note>`, to stdout; a FAIL's detail (the files, a gate tail) is printed above its line, and gitleaks' own output streams to the terminal before its line. Git calls use `gitRun(root, args, { cap: 60_000 })` (§4.9), not doctor's budget; the hook's git calls keep git's environment (`GIT_INDEX_FILE` names the temporary index of a partial commit, *measured*), so `diff --cached` and gitleaks see what is being committed.

**`COOKWRIGHT_SKIP`** (Leeka's E-218): a comma-separated list of check names in the environment; a named check is `SKIP  skipped by COOKWRIGHT_SKIP; say why in the commit message` and never runs, while the others still do. `COOKWRIGHT_SKIP=doc-sync git commit …` is the sanctioned escape for a commit with no doc implication; `--no-verify` still skips everything and is documented as the last resort. An unknown name in the list is reported on one line and ignored.

**`secrets`** (`src/lib/hooks/secrets.mjs`), the staged-diff scan:
- `probes.hasTool('gitleaks')` false → `SKIP  skipped, needs gitleaks, run setup (brew install gitleaks)`.
- Else run, through an injected probe `probes.scanStaged(root)` (default: `gitleaks git --pre-commit --staged --redact --verbose --no-color --no-banner --exit-code 3`, `spawnSync` with `stdio: ['ignore', 'inherit', 'inherit']` so the redacted output streams straight to the terminal and no `maxBuffer` can cut the scan short (a large staged dump would otherwise end in ENOBUFS and a false SKIP), 60 s timeout, cwd root, git's environment kept; *measured* in 8.30.1: the flags exist; exit 0 on nothing staged, on a clean diff and on a repo with no commits; exit 3 on a finding, on the initial commit too; exit 1 on a malformed `.gitleaks.toml` and on an unknown subcommand; `--redact` keeps the value out of both streams; without `--verbose` only a count prints, with it the rule id, file and line print with `REDACTED`; about 45 ms). `--exit-code 3` separates a finding from a failure to run: **exit 0 → PASS** `staged diff clean (gitleaks <version>)` — the version from `gitleaks version` (*measured*: prints exactly `8.30.1`), omitted when that fails; **exit 3 → FAIL** `secret(s) in the staged diff (values redacted above); remove them, or add an anchored allowlist entry to .gitleaks.toml, never a whole-file one`, gitleaks' own output having streamed above; **anything else, a timeout included → SKIP** `gitleaks did not run (exit N); run npx cookwright doctor` (a malformed `.gitleaks.toml`, or a gitleaks too old for the `git` subcommand, lands here with its own message on the terminal, so no version is pinned or parsed for gating; doctor's `tools.gitleaks` makes that state drift, §4.6).
- Never reads a file's content itself and never prints a value: gitleaks' redacted output is the only thing shown.

**`doc-sync`** (`src/lib/hooks/docsync.mjs`), the mechanism as config (§4.5): for each rule in `hooks.docSync`, `code = git diff --cached --name-only --no-renames --diff-filter=ACMRD -- <rule.code…>`; when non-empty, `docs =` the same with `rule.docs`; empty → the rule fails. Note: `<name>: <n> file(s) changed (<up to five, then "…">), but none of <docs> is staged; update the doc in this commit, or COOKWRIGHT_SKIP=doc-sync with the reason in the message`. No rules → `SKIP  no doc-sync rules configured (hooks.docSync in cookwright.json)`. Matching is git's own pathspec machinery, nothing of ours: `*` crosses `/`, `:!x` and `:(exclude)x` exclude, `:(glob)` is available. *Measured*: `git diff` honours a leading-star exclude (`':!*.test.mjs'`), while `git ls-files` drops the whole result on one, so the hook matches **only** through `git diff --cached`, never `ls-files`; `diff --cached` works on an unborn HEAD, under a partial commit (`GIT_INDEX_FILE`) and on `--amend`. A git exit other than 0 (an unknown pathspec magic, exit 128) is the harness's problem: the check's own `SKIP  doc-sync  could not run: <rule>: <git's stderr>` line, which leaves a `secrets` FAIL in the same run in force (disposition 9). **Merge commits**: a clean `git merge` runs no pre-commit; a `--no-commit` merge or a conflict resolution does, and `diff --cached` is then the whole merged side against the first parent, so a rule can fail for commits that each passed (*measured*). Expected; the escape with the reason is the answer, and the README says so.

**`gate`** (`src/lib/hooks/push.mjs`), tests on push. First `planChecks({ checks: gate.checks, hasTool })` from `src/lib/bundle/gate.mjs`: no checks → `SKIP  no gate checks configured (gate.checks)`; every check marked `skip` → `SKIP` naming them with their reasons (`runGate`'s refusal carries no names, so the hook plans first). Then `runGate({ repo, log, env })`: the same checks and skip rules as the bundle gate (`needs`, a command the shell cannot find → `skipped, needs X, run setup`); a `scriptProblems` refusal (an npm script the repo lacks) is `SKIP  gate  <the gate's refusal text>` (misconfiguration; doctor's `gate.scripts`, §4.6, reports it). **The gate commands run with git's hook variables removed from the environment** (`GIT_DIR`, `GIT_WORK_TREE`, `GIT_INDEX_FILE`, `GIT_PREFIX`, `GIT_COMMON_DIR`, `GIT_OBJECT_DIRECTORY`; githooks(5) says a hook working in another repository must clear them; *measured*: pre-push here exports `GIT_PREFIX`, `GIT_EDITOR` and `GIT_EXEC_PATH`, pre-commit `GIT_INDEX_FILE` and `GIT_PREFIX` too), so a user's suite that runs git in scratch repos, like this repo's own, is not pointed at the developer's repository; `runGate` gains an `env` option for it and `runCheck` passes it to `spawnSync`. A failing check prints its tail as `cmdGate` does, then `FAIL  gate  <names>`. **Every gate line on which a check ran carries the elapsed time**, PASS and FAIL alike (`PASS  gate  test (18.3 s)`, `FAIL  gate  test (40.1 s)`, the sum of the results' `ms`), so the cost of every push is visible (disposition 6). The gate's 30-minute cap stands: it is the user's own suite.

**pre-push stdin** (`<local ref> <local sha> <remote ref> <remote sha>` per line): read only when `!process.stdin.isTTY` (by hand, a TTY would block; `io.input` is the test seam). No lines (*measured*: git runs pre-push with empty stdin when everything is up to date) → both checks `SKIP  nothing to push`; every local sha the zero id (deletions only) → `SKIP  only deletions pushed`; otherwise both checks run. **They judge the working tree, not the pushed commit** (disposition 8): when the tree is dirty outside the bundle state, or any non-zero local sha is not HEAD (`git push origin other:main`, or an older commit), each line ends with `(judged on the working tree, not <sha8>)`; never a refusal, which would breed `--no-verify`. The README says the same in one sentence.

**`changelog`** (same file): maps `changelogState(repo)` from §4.4: `current` → PASS `CHANGELOG.md matches <n> release tag(s)`; `stale` → FAIL `out of date with the release tags; run npx cookwright changelog and commit`; `unmarked` → SKIP `not generated by cookwright; npx cookwright changelog --adopt replaces the file`; `missing` → SKIP `missing; run npx cookwright init`. It judges the checked-out tree, as every pre-push does, and prints no non-semver note (that is the command's, §4.4).

### 4.2 The shims and `core.hooksPath`

`src/lib/hooks/shims.mjs` holds `HOOKS_DIR = '.githooks'`, `HOOK_NAMES = ['pre-commit', 'pre-push']`, `shimText(name)`, `callLine(name)`, `callsCookwright(text, name)` and the fallback lines. It imports nothing (the shim is content written into the user's repo, like `HOOK_COMMAND` in `hosts.mjs`; the strings test exempts it with that reason). The shim, LF, mode `0755`:

```sh
#!/bin/sh
# Managed by cookwright (npx cookwright init). The logic is in the package; this file only calls it.
command -v node >/dev/null 2>&1 || { echo "cookwright pre-commit skipped, needs node, run setup"; exit 0; }
[ -f node_modules/cookwright/bin/cookwright.mjs ] || { echo "cookwright pre-commit skipped: package not installed (npm install)"; exit 0; }
node node_modules/cookwright/bin/cookwright.mjs hook pre-commit "$@"; s=$?
[ $s -eq 0 ] && exit 0
[ $s -eq 10 ] && exit 1
echo "cookwright pre-commit crashed (exit $s); the commit goes through unchecked"; exit 0
```

No `exec`: the mapping is what keeps a crash from blocking a commit (disposition 9), and a non-exec child still inherits stdin, which pre-push needs. `callLine(name)` is `node node_modules/cookwright/bin/cookwright.mjs hook <name> "$@"`. "The file calls cookwright" (`callsCookwright(text, name)`) accepts **only forms in which a finding's exit code reaches git**: our own shim byte for byte ("ours"); a trimmed line equal to `exec <callLine>`; a trimmed line equal to `<callLine> || exit 1` or `<callLine> || exit $?`; or `<callLine>` alone as the file's **last** non-blank, non-comment line. `<callLine> || true`, any other suffix, or the call followed by further commands is **not** a call (the exit status would be swallowed), and reads as "does not call cookwright". Never a substring (stage 1's rule). A user's `exec` form passes a crash's code to git too, which is their choice. No `npx` (stage 1's measurement). Relative paths work because git runs hooks from the work tree root and resolves a relative `core.hooksPath` against it (*measured*, from a subdirectory and from a linked worktree too). A linked worktree without `node_modules` prints the not-installed line and exits 0; that is B-002's family (§9).

### 4.3 init: the hooks step

Step 8, after `.gitignore` (§4.4 of the stage-1 plan), `src/lib/init/hooks.mjs`, three rows: `hooks.path`, `.githooks/pre-commit`, `.githooks/pre-push`. Preflight first:

- The **effective** `core.hooksPath` with its scope: `git config --show-scope --get core.hooksPath` (exit 1 = unset anywhere; the scope word is `local`, `worktree`, `global` or `system`; *measured*: `local` from a linked worktree too, where `--show-origin` would print an absolute path, which must never reach a readout). Then `git rev-parse --git-path hooks` (the real hooks dir: `.git/hooks` when unset, the common dir's from a linked worktree, `.githooks` when set; *measured*; its output is cwd-relative, and `gitRun` runs at the root) and the names of its non-`.sample` entries when the path is unset. And the state of `.githooks/pre-commit` and `.githooks/pre-push` whatever the path says.
- **Foreign hooks** — hooksPath set to anything but the relative `.githooks` (an absolute path naming this repo's own `.githooks` included), or set from a scope other than `local` (a global `core.hooksPath` would be silently overridden by a local one), or unset while the hooks dir holds a non-sample file, **or a `.githooks/pre-commit` or `pre-push` that is neither ours nor calls cookwright** (a repo already using `.githooks` for its own hooks, disposition 13) → all three rows `skipped`: `core.hooksPath is <x> (<scope>): hooks are managed elsewhere, cookwright's are not installed`, `<dir> has <names>: cookwright's hooks are not installed`, or `.githooks/<name> is not cookwright's: cookwright's hooks are not installed` (the enhancement in §9 names the way out). Nothing written, nothing configured.
- Otherwise `hooks.path`: unset → `wrote` with a **git write** `['config', '--local', 'core.hooksPath', '.githooks']`; equal to `.githooks` from the local scope → `kept`.
- **Linked worktrees** (disposition 10): `--local` is the shared repository config, so the path applies to every worktree of the repo, and a worktree whose branch does not carry `.githooks/` runs no hook at all, silently (*measured*). doctor in that worktree reports `hooks.pre-commit FAIL missing (run init)`, and init there writes the shims on that branch. Accepted; the README names it.
- Each shim: absent → `wrote` (mode 0755); ours byte-for-byte and executable → `kept`; **any file that calls cookwright but is not executable → `updated` (the mode only; chmod is not an edit of a script)**; a user's file that calls cookwright → `kept  calls cookwright; the rest is yours`; a file that does not → `kept  does not call cookwright; add the line: <callLine>` (init never edits a user's script; doctor FAILs it, §4.6); not a file → refused in preflight (`notAFile`).

`files.mjs` grows two small things: a write may carry `mode` (`writeFileSync(abs, content, { mode })` **then `chmodSync`**, since the mode option does not touch an existing file, *measured*; Windows ignores it and git's `core.fileMode` is the user's), and a write may be `{ git: [args] }`, run by `applyRows` through `gitRun` **after** every file write of the run, so the path is never activated before both shims exist and are executable (finding 6); a git failure then is a `Refusal` with git's stderr that names the two inert shim files it leaves behind, which the next init reports `kept` and completes. `refuseLinks` looks at file writes only. `--dry-run` writes neither files nor config. The fresh config (§4.5) gains `hooks: { docSync: [] }`; an existing config is kept, as ever.

### 4.4 `cookwright changelog`

`npx cookwright changelog [--check | --unreleased | --adopt]` (`src/changelog.mjs`, library `src/lib/changelog/`: `tags.mjs`, `commits.mjs`, `render.mjs`, `state.mjs`). Two flags together, a positional or an unknown flag → usage, exit 2. Not a work tree, or no config → refusal, exit 2. Git calls go through `gitRun(root, args, { cap: 60_000 })` (§4.9), a failure a refusal with git's stderr, with one exception below.

**Unborn HEAD** (`git rev-parse --verify -q HEAD` ≠ 0; every user's repo starts there, and `git tag --merged HEAD` and `git log HEAD` both exit 128 on it, *measured*): zero tags, zero commits. `--check` compares against the template; `--unreleased` prints `nothing unreleased (no commits yet)`.

**Tags:** `git tag -l 'v[0-9]*.[0-9]*.[0-9]*' --merged HEAD --format=%(refname:strip=2)%1f%(objecttype)` — **`%1f`, not `%x1f`**: ref-filter formats (`git tag`, `for-each-ref`) take `%<hex>`, and `%x1f` prints literally there (*measured*, both reviewers and here: `%1f` yields byte 037); `%x1f` stays only in the `git log --format` call, which is a pretty format. A low-level test asserts the raw tuple git returns before any rendering test. Names kept only when they match `^v(\d+)\.(\d+)\.(\d+)$` (strict: `v1.0.0-rc1` matches the glob and would sort by `NaN`), sorted numerically; each skipped tag is one stderr line `skipping non-semver tag <t>` **from the command only**, never from the pre-push check. `--merged HEAD` so a branch is judged against the releases it holds. **Order is version order** (disposition 12): a release's range is `<previous version>..<tag>`, which is deterministic and byte-stable whatever the graph; when a previous version is not an ancestor of the next (`git merge-base --is-ancestor`, one call per pair: a backport tagged after a later release, a merged maintenance branch), the command prints `v1.1.1 is not an ancestor of v2.0.0; the v2.0.0 section covers commits not in v1.1.1` on stderr and renders anyway. A test holds the merged-maintenance-branch case to that output.

**Release metadata**, from the tag body **only when `%(objecttype)` is `tag`** (annotated). For a lightweight tag `%(contents)` is the pointed commit's message (*measured*), so it is **not** read: a lightweight tag has no metadata. For an annotated tag `%(contents)` is the subject, a blank line, the body (and, for a signed tag, a `-----BEGIN PGP SIGNATURE-----` block, which is dropped from that line on; unmeasured, no key here). Lines `key: value` with `key` matching `^([a-z][\w-]*):(?:\s|$)` (the space after the colon keeps `https://…` on a continuation line, and any `word:` run into prose, out of the keys); a value continues over following lines until the next key line or a blank line; the subject counts when it is itself a key line (`git tag -a v1.0.0 -m 'released: 2026-10-15'`), otherwise it is ignored. `released` is the date in the heading; `note` renders as a blockquote; **every other key renders as `**Key.** value`** in body order, so Leeka's `ios`, `android` and `store` need no code of their own.

**Commits:** `git -c log.showSignature=false log --format=%H%x1f%s <prev>..<tag>` (the first tag: its whole history; an empty range is fine; the `-c` keeps a signer's `log.showSignature=true` from adding gpg lines that would make the render machine-dependent). `^([a-z]+)(?:\(([^)]*)\))?(!)?: (.+)$`; sections `feat` → Features, `fix` → Fixes, `perf` → Performance; `!` → `**BREAKING** `; a scope → `**scope** — `; the 8-char sha in backticks. Everything else is counted as internal: `_N commits in this release, M internal (docs, chore, refactor, tests, tooling)._`

**Render:** the header is **the template** `src/lib/templates/CHANGELOG.md`, which init already seeds, rewritten to be the generated file's header: `# Changelog`, a blank line, the marker line `<!-- cookwright:changelog -->`, then one paragraph: generated by `npx cookwright changelog` from the commits between release tags (`vX.Y.Z`, annotated), not edited by hand (the next run reverts it); unreleased work is not stored, `--unreleased` computes it; a release's date and notes come from its annotated tag body (`released: YYYY-MM-DD`, `note: …`, any `key: value`); then `---`. No `{{…}}` placeholder (init reads it verbatim). Sections newest first, `## X.Y.Z — <released>` (or `## X.Y.Z`), one blank line between blocks, no trailing spaces, so a user's prettier leaves it alone (not verified against prettier: no dependency; if it ever disagrees, that is a bug to measure). **With zero tags the render is the template, byte for byte** (a test holds them equal), so a fresh repo passes `--check` from before its first commit (the developer's requirement), and init's `homes.changelog` row and the generator agree. The section titles and the internal line are content of the generated file (`render.mjs` is exempt in the strings test with that reason); the command's own lines are in `messages.changelog`.

**`changelogState(repo) → { state: 'missing' | 'unmarked' | 'stale' | 'current', tags }`** (`state.mjs`) is what the command and the pre-push check share: `missing` (no file at `paths.changelog`), `unmarked` (no marker line), then render and compare **LF-normalised** (`readLF`, as the other file checks do, so a CRLF checkout on Windows is not `stale`; the file is always written LF). doctor's `homes.changelog` reads only the marker (§4.6) and does not import it: no `git log` per tag inside the 1.8 s budget.

**Writes refuse links**, as init does (stage 1's rule, findings 2 and 21): before writing `paths.changelog` the command runs the same check as `refuseLinks` (`linkOnPath`, exported from `src/lib/init/files.mjs`) on the target and every directory between the root and it, and refuses with the same `symlink` message, so a changelog that is a link to a file outside the repo, or under a linked `docs/`, is never written through; a test holds the external target byte-identical after a refused `--adopt`.

**Modes:** default (no flag) writes `paths.changelog` and prints `<file> regenerated from <n> release tag(s)`, **except on an `unmarked` file, which it refuses** (exit 2: `<file> is not generated by cookwright; --adopt replaces it, keep a copy of what you want from it`), so a hand-kept changelog is never lost to a plain run; `--adopt` writes regardless. `--check`: `missing` → exit 1 `missing; run npx cookwright changelog`; `unmarked` → exit 1 `not generated by cookwright; npx cookwright changelog --adopt replaces the file`; `stale` → exit 1 `out of date with the release tags; run npx cookwright changelog and commit`; `current` → exit 0 `up to date (<n> release tag(s))`. `--unreleased`: `lastTag..HEAD` (or all of HEAD with no tag), rendered as one section headed `## Unreleased — <n> commit(s) since <tag>` (no tag: `## Unreleased — <n> commit(s), no release tag yet`) to stdout, nothing written; no commits → `nothing unreleased since <tag>`.
