## 1. Context

Level 0 is "hooks, state homes, backlog, changelog, doctor, setup" (charter). Stages 1 and 2 shipped everything but setup, and left the package unable to carry its own agent surface to a user: `hosts/` and `docs/playbook.md` sit outside `packages/cookwright/` and are not in the tarball (*measured*: `npm pack --dry-run` lists bin, src, schema only); `bundle status` prints `Workflow({ scriptPath: 'hosts/claude/workflows/bundle-phase.js' })`, a path no user repo has; and the `/bundle` skill reaches this repo only through tracked symlinks under `.claude/` that nothing writes for a user (*measured*: `.claude/skills/bundle -> ../../hosts/claude/skills/bundle`, `.claude/workflows/*.js` likewise, tracked as mode 120000, and this session lists `/bundle`, `/bundle-phase` and `/docs-audit`, so Claude Code loads skills and workflows through in-repo symlinks).

Stage 1 also wrote `paths.playbook: "docs/playbook.md"` into every fresh user config while no step ever wrote a playbook there, so every user repo names a file that does not exist. That is the first real config migration (E-013), which the charter's fourth property ("fixes land by a version bump, with config migrations between versions") wants in place before `version` ever moves.

What the hosts offer (*documented*):

- **Claude Code** reads project skills from `.claude/skills/<name>/SKILL.md` (start directory up to the repo root), and "a `<skill-name>` entry may be a symlink to a directory elsewhere"; named workflows load from `.claude/workflows/`; a Workflow script must be readable by the session (anything under the working directory is). Plugins can ship `skills/` and `workflows/` too, but a project-scope marketplace needs a trust dialog, is never added in cloud sessions, and the relative-path form of `extraKnownMarketplaces` in a committed `settings.json` is not documented.
- **Codex** scans `.agents/skills/` in every directory from the cwd up to the repo root, "supports symlinked skill folders and follows the symlink target" (since rust-v0.80.0), reads `AGENTS.md` natively with `AGENTS.override.md` replacing it per directory, has a `SessionStart` command hook in `<repo>/.codex/hooks.json` that the user trusts once with `/hooks` (the binary carries a `trusted_hash` beside the hook entries, *measured* with `strings`, so a rewrite of the file likely needs trusting again), and has no workflow mechanism. No config key adds a skills directory.

## 2. Decisions

**Decision 1, decided by the developer on 2026-10-16 (plan approval): pointers, as recommended below; the 2026-10-15 plugin decision is superseded.** The route for Claude Code skills and workflows: init writes symlinks `.claude/skills/<name>` and `.claude/workflows/<name>.js` into the installed package, what this repo runs on today, for these reasons: it is the one mechanism Codex needs anyway (`.agents/skills/` pointers, the same decision); it is *measured* for in-repo targets while the plugin's project-scope marketplace is a trust dialog that never runs in cloud sessions and a settings shape the docs do not cover; and a pointer follows the package version with no second install or `claude plugin update` (charter property 4). What the user loses, said plainly: namespacing (`/cookwright:setup` would never collide with a skill of their own; here a user's own `setup` shadows ours with a WARN), `/plugin` discoverability, and Windows (git checks a symlink out as a text file without `core.symlinks`; backlogged beside B-008/B-009), and the pointers resolve only for a local install under `node_modules` (not yarn PnP, not a global install; the README says so). **Precondition at kickoff (rule 3):** before `bundle init`, one Claude Code session in a scratch repo measures three things: a `.claude/skills/<name>` symlink into `node_modules/<pkg>/skills/<name>` lists the skill; the same link dangling (no `node_modules`) neither lists it nor breaks the session; and **one named workflow run** (`Workflow({ name })`) through a `.claude/workflows/<name>.js` symlink into `node_modules/<pkg>/workflows/<name>.js` runs to its return value, since the bundle runner is what depends on that route (the developer's amendment, 2026-10-16). The orchestrator runs it, or the developer opens the session. If any of the three fails, §4.4's Claude half becomes a plugin manifest under `hosts/claude/.claude-plugin/` plus a project marketplace written into `.claude/settings.json`, the Codex half stays, and the rest of the plan is unchanged.

**Decision 2, decided by the developer on 2026-10-16: the skill is named `setup`**, as E-012 names it, although a generic name is the one a user's own skill most plausibly shadows (this machine lists three `setup-*` skills); a later rename costs one `updated` row per user.

### 4.3 `cookwright migrate [--dry-run]` and version 2 (E-013)

`CONFIG_VERSION = 2`. `src/lib/migrations.mjs` holds `MIGRATIONS`, pure functions keyed by the version a step starts from: `1: (raw, ctx) => raw'` drops `paths.playbook` when its value is the stage-1 default `docs/playbook.md` and `ctx.exists(rel)` is false, and keeps it otherwise (the user's own playbook). Nothing else changes in 1→2.

**The loader** (`config.mjs`, `loadConfig`): `raw.version` an integer below `CONFIG_VERSION` and every step known → the chain runs in memory on the raw object before `withDefaults`, the config loads, and `config.migratedFrom = 1` is set so doctor's `config` check is WARN `valid at version 2 after migrating from 1 in memory; run npx cookwright migrate to write it`; above → the load fails with `version 3 is newer than this cookwright's 2: update cookwright (npm install cookwright@latest)`; anything else keeps today's line. init's `configStep` keeps the in-memory config (a row `kept  cookwright.json  version 1, migrate to write version 2`); the hook runs every check.

**The command** (`src/migrate.mjs`, registered in `cli-main.mjs`, usage `<init|doctor|changelog|hook|migrate|bundle>`): find the config as doctor does (none → refusal); read the **raw** JSON (never `withDefaults`); `version === CONFIG_VERSION` → `cookwright.json: already at version 2`, exit 0; newer → the loader's refusal; else apply each step with one line each (`1 → 2: paths.playbook dropped (docs/playbook.md was never written; the package's playbook applies)` / `… kept (your own playbook)`), validate the result with `validateConfig(withDefaults(result))` and refuse writing nothing if invalid; write with the file's indent, line ending and final newline (`indentOf`/`serialize` move from `init/claude.mjs` to `init/files.mjs` as `reserialize(obj, text)`), with the `relaid` note when re-serialising changes more than the keys (a one-line array expands, as this repo's `hosts` and gate check will, *measured*); through `refuseLinks`. `--dry-run` prints and writes nothing. Tests inject the table (`io.migrations`).

### 4.4 The host table and the pointers (E-007)

`HOSTS.claude` gains `skillsDir: '.claude/skills'`, `workflowsDir: '.claude/workflows'`; `workflows: 'hosts/claude/workflows'` becomes package-relative. `HOSTS.codex`: `rules: ['AGENTS.md']`, `shadowing: ['AGENTS.override.md']`, `importLine: null`, `skillsDir: '.agents/skills'`, `workflowsDir: null`, `settings: '.codex/hooks.json'`, `hookMatcher: 'startup|resume'`. **Hook commands become a function of the config root's place**: `hookCommand(rel)` where `rel` is the config root from the top (`''` at the top): Claude's `cd "${CLAUDE_PROJECT_DIR:-.}/<rel>"`, Codex's `cd "$(git rev-parse --show-toplevel 2>/dev/null || echo .)/<rel>"` (Codex runs hooks in the session cwd), the rest of the line unchanged. Detection stays equality, against the text expected for this repo; the stage-1 text joins `hookCommandsPast` (WARN past → init replaces), so an existing user at the top sees `kept`. This closes the hook half of B-002 for nested roots (disposition 6).

**Pointers** (`init/pointers.mjs`, a step per configured host, `flatMap` over `config.hosts`; `hostStep` no longer takes the first host only). What the package ships: directories under `PACKAGE_ROOT/skills` holding a `SKILL.md` (never a `.DS_Store`), and `*.js` under `PACKAGE_ROOT/hosts/<host>/workflows`; a skill that needs workflows (`bundle`) is written for hosts with `workflowsDir` only (disposition 11; `SKILLS` in `hosts.mjs` says which). Pointers live at the work tree's top, where a session starts, with `placement()` from `doctor/hooks.mjs:38`; the target is the POSIX relative path from the pointer's directory to `installedPackage(repo)` (disposition 6; absent → the config-root form). Row states, by `lstat` and `readlink`, **text first**:

| found at `<host.skillsDir>/<name>` | row |
|---|---|
| nothing | `wrote` (a `link` write); `ignored by git (.claude/ in a global ignore: a fresh clone has no pointer)` appended when the `ignored` probe says so |
| a symlink whose text is one of ours | `kept` (`resolves` / `not installed where it points (npm install)`) |
| a symlink of other text that resolves to nothing | `updated  earlier pointer replaced` |
| a symlink of other text that resolves | `skipped  your own link; cookwright's <name> is not reachable` |
| a directory or file | `skipped  your own <name> shadows cookwright's` |
| the pointer's directory is itself a symlink | `skipped  <dir> is a link of yours` (not a whole-run refusal; `refuseLinks` still applies to every other write) |

`init/files.mjs` gains the `link` write (`{ rel, link: target }`: a dangling symlink at `rel` is removed, then `symlinkSync(target, abs)`); `refuseLinks` exempts the row's own target. A `symlinkSync` that throws (`EPERM` on Windows without Developer Mode, a filesystem without links) is reported after the rows as `pointer <rel> not written: this filesystem refuses symbolic links (<code>)` and the run continues (rule 1); doctor on `win32` reports a missing pointer as WARN naming the backlog item, FAIL elsewhere. `steps.mjs`: `HOST_STEPS[host]` gains `pointers`; the Codex `rules` row derives from the block row (the block step writes `AGENTS.md` in the same run; a fresh `--hosts codex` repo must not read "kept" for a file not yet written); the Codex `hook` step writes or merges `.codex/hooks.json` through `init/hostfile.mjs`, the settings logic of `init/claude.mjs` generalised to a file name and a matcher, and merges only when the command is absent, so the file is rewritten as rarely as possible (trust).

**doctor** (`doctor/hosts.mjs`, a shared reader as `hooks.mjs` is): `host.pointers` judges every configured host and joins the notes (`claude: 2 skills, 2 workflows; codex: 1 skill`), worst status first; a host without workflows contributes its skills only. `host.rules` and `host.hook` judge every host too: Codex `rules` PASS when `AGENTS.md` is at the root and no `AGENTS.override.md` beside it, WARN naming the override otherwise; Codex `hook` PASS `.codex/hooks.json carries the doctor hook (whether it is trusted is yours: /hooks)`, FAIL absent, WARN past. `levels.mjs`: Level 0 `requires` gains `host.pointers`. The doctor fixture (`level0()` in `doctor.test.mjs:68`) writes the pointer targets (`skills/<name>/SKILL.md`, `hosts/claude/workflows/*.js`), not the bin alone.

### 4.5 The `/setup` skill (E-012)

`packages/cookwright/skills/setup/SKILL.md`, frontmatter `name: setup`, a description naming when: a doctor line that is not PASS, an update of the package, adding a host. First line: Level 0. It is prose the agent follows; the logic stays in the CLI (rule 4). It exists only once init has run, so the first two commands live in the README (§7.5), not here. The procedure:

1. `npx cookwright doctor`, read whole.
2. For each line that is not PASS, in readout order, the recipe table: `config` WARN migrated in memory → `npx cookwright migrate`, show its lines; `config` FAIL newer → `npm install cookwright@latest`, ask first (a dependency change); `rules.block` stale, `host.hook` past, `host.pointers` missing or earlier → `npx cookwright init`; `host.pointers` not installed → `npm install`; `host.rules` shadowed → the README's import paragraph; `tools.gitleaks` unverified → hand over the platform's install command (`brew install gitleaks`, `apt`, `winget`), the developer's hands, then doctor again; `hooks.path` weak (husky, lefthook) → explain, offer the README's one-line call, leave it (E-018); `homes.changelog` weak → ask, then `changelog --adopt` after they keep a copy; `gate.scripts` FAIL → name the script to fix; `gate.scripts` PASS with no checks (an Expo scaffold has no test script, stage-1 QA round 2) → say pre-push runs nothing and offer a gate check (`tsc --noEmit`, `expo lint`, their call), writing it into `gate.checks` with consent; `secrets.env` → say Level 2 replaces it, never open the file.
3. Adding a host: edit `hosts` in `cookwright.json` with consent (init never edits an existing config), then `npx cookwright init`; for Codex say to trust the hook with `/hooks`, and again after any rewrite of the file.
4. Stop at `level N declared: complete`; print the `next:` line; name the files init wrote so they commit them by path (`git add <paths>`, never `-A`).

Rules in the skill: never write an env file, never `--no-verify`, never a secret's value in the transcript, no state of its own (doctor is the state), every install outside the repo is the developer's hands.

## 6. Tests

Vitest, scratch repos through `test-helpers.mjs`; `linkPackage(root)` symlinks `node_modules/cookwright` to the package (the stage-2 end-to-end hooks test's pattern) and `.git/info/exclude` hides it. No network, no env file.
