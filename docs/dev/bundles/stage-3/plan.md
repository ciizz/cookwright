## 1. Context

Level 0 is "hooks, state homes, backlog, changelog, doctor, setup" (charter). Stages 1 and 2 shipped everything but setup, and left the package unable to carry its own agent surface to a user: `hosts/` and `docs/playbook.md` sit outside `packages/cookwright/` and are not in the tarball (*measured*: `npm pack --dry-run` lists bin, src, schema only); `bundle status` prints `Workflow({ scriptPath: 'hosts/claude/workflows/bundle-phase.js' })`, a path no user repo has; and the `/bundle` skill reaches this repo only through tracked symlinks under `.claude/` that nothing writes for a user (*measured*: `.claude/skills/bundle -> ../../hosts/claude/skills/bundle`, `.claude/workflows/*.js` likewise, tracked as mode 120000, and this session lists `/bundle`, `/bundle-phase` and `/docs-audit`, so Claude Code loads skills and workflows through in-repo symlinks).

Stage 1 also wrote `paths.playbook: "docs/playbook.md"` into every fresh user config while no step ever wrote a playbook there, so every user repo names a file that does not exist. That is the first real config migration (E-013), which the charter's fourth property ("fixes land by a version bump, with config migrations between versions") wants in place before `version` ever moves.

What the hosts offer (*documented*):

- **Claude Code** reads project skills from `.claude/skills/<name>/SKILL.md` (start directory up to the repo root), and "a `<skill-name>` entry may be a symlink to a directory elsewhere"; named workflows load from `.claude/workflows/`; a Workflow script must be readable by the session (anything under the working directory is). Plugins can ship `skills/` and `workflows/` too, but a project-scope marketplace needs a trust dialog, is never added in cloud sessions, and the relative-path form of `extraKnownMarketplaces` in a committed `settings.json` is not documented.
- **Codex** scans `.agents/skills/` in every directory from the cwd up to the repo root, "supports symlinked skill folders and follows the symlink target" (since rust-v0.80.0), reads `AGENTS.md` natively with `AGENTS.override.md` replacing it per directory on the path from the root to the cwd, has a `SessionStart` command hook in `<repo>/.codex/hooks.json` that the user trusts once with `/hooks` (the binary carries a `trusted_hash` beside the hook entries, *measured* with `strings`, so a rewrite of the file likely needs trusting again), and has no workflow mechanism. No config key adds a skills directory.

**The kickoff precondition, measured on 2026-10-16** (recorded in the state): in a scratch repo, one-shot Claude Code sessions listed and invoked a skill through a `.claude/skills/<name>` symlink into `node_modules/<pkg>/skills/<name>` (the session replied the skill's own text), ran the **named** workflow `Workflow({ name })` through a `.claude/workflows/<name>.js` symlink into `node_modules/<pkg>/workflows/` to its return value, and, with the same two links dangling, listed nothing and raised no error. The `scriptPath` form through a link was not measured; §4.1 prints the named form.

## 2. Decisions

**Decision 1, decided by the developer on 2026-10-16 (plan approval): pointers; the 2026-10-15 plugin decision is superseded.** The route for Claude Code skills and workflows: init writes symlinks `.claude/skills/<name>` and `.claude/workflows/<name>.js` into the installed package, what this repo runs on today, for these reasons: it is the one mechanism Codex needs anyway (`.agents/skills/` pointers, the same decision); it is *measured* (above) while the plugin's project-scope marketplace is a trust dialog that never runs in cloud sessions and a settings shape the docs do not cover; and a pointer follows the package version with no second install or `claude plugin update` (charter property 4). What the user loses, said plainly: namespacing (`/cookwright:setup` would never collide with a skill of their own; here a user's own `setup` shadows ours with a WARN), `/plugin` discoverability, and Windows (git checks a symlink out as a text file without `core.symlinks`; backlogged beside B-008/B-009), and the pointers resolve only for a local install under `node_modules` (not yarn PnP, not a global install; the README says so).

**Decision 2, decided by the developer on 2026-10-16: the skill is named `setup`**, as E-012 names it, although a generic name is the one a user's own skill most plausibly shadows (this machine lists three `setup-*` skills); a later rename costs one `updated` row per user.

### 4.3 `cookwright migrate [--dry-run]` and version 2 (E-013)

`CONFIG_VERSION = 2`. `src/lib/migrations.mjs` holds `MIGRATIONS`, pure functions keyed by the version a step starts from: `1: (raw, ctx) => raw'` drops `paths.playbook` when its value is the stage-1 default `docs/playbook.md` and `ctx.exists(rel)` is false, and keeps it otherwise (the user's own playbook). Nothing else changes in 1→2.

**The loader** (`config.mjs`, `loadConfig`): `raw.version` an integer below `CONFIG_VERSION` and every step known → the chain runs in memory on the raw object before `withDefaults`, the config loads, and `config.migratedFrom = 1` is set so doctor's `config` check (`doctor/basics.mjs`, `checkConfig`) is WARN `valid at version 2 after migrating from 1 in memory; run npx cookwright migrate to write it`; above → the load fails with `version 3 is newer than this cookwright's 2: update cookwright (npm install cookwright@latest)`; anything else keeps today's line. The schema's `version` is `enum: [1, 2]` with the description saying 1 is migrated in memory; the parity test holds schema versions = `{CONFIG_VERSION} ∪ keys(MIGRATIONS)`. init's `configStep` keeps the in-memory config (a row `kept  cookwright.json  version 1, migrate to write version 2`); the hook runs every check.

**The command** (`src/migrate.mjs`, registered in `cli-main.mjs`, usage `<init|doctor|changelog|hook|migrate|bundle>`): find the config as doctor does (none → refusal); read the **raw** JSON (never `withDefaults`); `version === CONFIG_VERSION` → `cookwright.json: already at version 2`, exit 0; newer → the loader's refusal; else apply each step with one line each (`1 → 2: paths.playbook dropped (docs/playbook.md was never written; the package's playbook applies)` / `… kept (your own playbook)`), validate the result with `validateConfig(withDefaults(result))` and refuse writing nothing if invalid; write with the file's indent, line ending and final newline (`indentOf`/`serialize` move from `init/claude.mjs` to `init/files.mjs` as `reserialize(obj, text)`), with the `relaid` note when re-serialising changes more than the keys (a one-line array expands, as this repo's `hosts` and gate check will, *measured*); through `refuseLinks`. `--dry-run` prints and writes nothing. Tests inject the table (`io.migrations`).

### 4.4 The host table and the pointers (E-007)

`HOSTS.claude` gains `skillsDir: '.claude/skills'`, `workflowsDir: '.claude/workflows'`; `workflows: 'hosts/claude/workflows'` becomes package-relative. `HOSTS.codex`: `rules: ['AGENTS.md']`, `shadowing: ['AGENTS.override.md']`, `importLine: null`, `skillsDir: '.agents/skills'`, `workflowsDir: null`, `settings: '.codex/hooks.json'`, `hookMatcher: 'startup|resume'`, `hookCommand`: Claude's line with `cd "${CLAUDE_PROJECT_DIR:-.}"` replaced by `cd "$(git rev-parse --show-toplevel 2>/dev/null || echo .)"` (Codex runs hooks in the session cwd); no path is interpolated. **A known limit, stated in the README's Codex paragraph (disposition 27):** the session-start readout therefore judges from the work tree's top, so an `AGENTS.override.md` in a subdirectory the session started in is caught by a by-hand `npx cookwright doctor` run there, not by the hook line; a `doctor --from <dir>` is backlogged. **Claude's hook command and the git shims are unchanged** (disposition 16). `SKILLS` in `hosts.mjs` lists what the package ships with its level and needs: `setup` (level 0), `bundle` (level 2, needs workflows).

**Pointers** (`init/pointers.mjs`, a step per configured host, `flatMap` over `config.hosts`; `hostStep` no longer takes the first host only). What the package ships: directories under `PACKAGE_ROOT/skills` holding a `SKILL.md` (never a `.DS_Store`), and `*.js` under `PACKAGE_ROOT/hosts/<host>/workflows`; a skill that needs workflows is written for hosts with `workflowsDir` only (disposition 11). Pointers live at the work tree's top, where a session starts, with `placement()` from `doctor/hooks.mjs:38`; the target is the POSIX relative path from the pointer's directory to `installedPackage(repo)` (disposition 6; absent → the config-root form). **Ours** is a link whose text matches `(../)*[<rel>/]node_modules/cookwright/(skills|hosts/<host>/workflows)/<name>` or an entry of `POINTER_TEXTS_PAST` (empty in this stage; the `hookCommandsPast` pattern). Row states, by `lstat` and `readlink`, **text first, resolution never deciding ownership**:

| found at `<host.skillsDir>/<name>` | row |
|---|---|
| nothing | `wrote` (a `link` write); `ignored by git` appended when the `ignored` probe says so |
| a link whose text is the current form | `kept` (`resolves` / `not installed where it points (npm install)`) |
| a link whose text is a past form | `updated  earlier pointer replaced` (removed, then rewritten) |
| any other link, dangling or resolving | `skipped  your own link; cookwright's <name> is not reachable through it` |
| a directory or file | `skipped  your own <name> shadows cookwright's` |
| a symlinked component anywhere on the pointer's parent path | `skipped  <component> is a link of yours` (never a whole-run refusal) |

`init/files.mjs` gains the `link` write (`{ rel, link: target }`: a past-form link at `rel` is removed, then `symlinkSync(target, abs)`); `refuseLinks` exempts the final pointer only. A `symlinkSync` that throws is reported after the rows as `pointer <rel> not written: this filesystem refuses symbolic links (<code>)`, the run continues (rule 1) and exits as doctor does; Windows is backlogged beside B-008/B-009 and a non-Windows filesystem refusing links as §9 (g) (dispositions 19 and 26). `steps.mjs`: `HOST_STEPS[host]` gains `pointers`; the Codex `rules` row derives from the block row (the block step writes `AGENTS.md` in the same run); the Codex `hook` step writes or merges `.codex/hooks.json` through `init/hostfile.mjs`, the settings logic of `init/claude.mjs` generalised to a file name and a matcher: a hook is identified by command **and** matcher, a hook with the command and a wrong matcher is `updated`, and the file is otherwise rewritten as rarely as possible (trust).

**doctor** (`doctor/hosts.mjs`, a shared reader as `hooks.mjs` is): `host.pointers` judges every configured host and joins the notes (`claude: 2 skills, 2 workflows; codex: 1 skill`), worst status first. Per pointer: ours and resolving → PASS; ours and not resolving → WARN not installed; ours, untracked and ignored by git → WARN `ignored by git; git add -f <path> to track it`; missing → FAIL `run init` when the piece's level is at or below the declared level, else WARN `<name> (Level 2) not required at level 0; run init to add it`; a past form → FAIL `earlier pointer (run init)`; the user's own → WARN naming it; on `win32` a missing pointer is WARN naming the backlog item. `host.rules` and `host.hook` judge every host too: Codex `rules` PASS when `AGENTS.md` is at the root and no `AGENTS.override.md` lies on the path from the invocation directory up through the root (`shadowingFiles` with the host's list, root-relative names), WARN naming the override otherwise; Codex `hook` PASS `.codex/hooks.json carries the doctor hook (whether it is trusted is yours: /hooks)` on command and matcher, WARN on the command with another matcher, FAIL absent. `levels.mjs`: Level 0 `requires` gains `host.pointers`. ### 4.5 The `/setup` skill (E-012)

`packages/cookwright/skills/setup/SKILL.md`, frontmatter `name: setup`, a description naming when: a doctor line that is not PASS, an update of the package, adding a host. First body line after the frontmatter: Level 0. It is prose the agent follows; the logic stays in the CLI (rule 4). It exists only once init has run, so the first two commands live in the README (§7.5), not here. **The procedure is a loop**: run `npx cookwright doctor`, read it whole, apply exactly one remedy from the recipe table to the first line that is not PASS, run doctor again, and repeat until the level line reads `complete` or every remaining line is a chosen state the table says to explain and stop at; never act on a readout older than the last remedy.

The recipe table, exhaustive by check, status and host:

- `config` WARN migrated in memory → `npx cookwright migrate`, show its lines. `config` FAIL newer → `npm install cookwright@latest`, ask first (a dependency change). `config` FAIL invalid (any other loader line) → show the line, fix the named key by hand with consent.
- `rules.block` stale or absent; `host.hook` past or absent; `host.pointers` missing or earlier; Codex `host.hook` with another matcher → `npx cookwright init`. `rules.block` newer (the block was written by a newer cookwright) → `npm install cookwright@latest`, ask first. `rules.block` malformed (init refuses it too) → show the reason, repair the markers by hand with consent. `host.hook` invalid JSON → show the parse error, repair the file by hand with consent. `host.pointers` not installed → `npm install`. `host.pointers` ignored by git → `git add -f <the named path>` with consent. `host.pointers` your own (a link or a directory of the user's) → chosen state: explain that cookwright's skill is unreachable under that name, stop. `host.pointers` not required at level 0 (a Level 2 pointer removed) → chosen state: say `init` would write it back, stop. `host.pointers` on Windows → explain, name the backlog item, stop.
- `host.rules` shadowed (Claude: a `CLAUDE.md`, `.claude/CLAUDE.md` or `CLAUDE.local.md`) → the README's import paragraph, with consent. `host.rules` old Claude Code (older than 2.1.281) → `npx cookwright init` writes the import; say an update of Claude Code is the other way. `host.rules` override (Codex: an `AGENTS.override.md`) → chosen state: explain that Codex reads the override instead of `AGENTS.md`, stop. `host.rules` unverified (no `claude` on PATH) → explain, stop.
- `git` WARN (the base branch is missing) → create it or set `baseBranch`, with consent.
- **Any line the table does not name** → show it, say the table has no recipe for it, stop (rule 3: no improvised remedy).
- `tools.gitleaks` unverified → hand over the platform's install command (`brew install gitleaks`, `apt`, `winget`), the developer's hands, then doctor again. `tools.gitleaks` FAIL (a malformed `.gitleaks.toml`) → show the line, stop.
- `hooks.path` weak (husky, lefthook, a hook of their own) → chosen state: explain, offer the README's one-line call, stop (E-018). `hooks.path` FAIL unset, `hooks.pre-commit`/`pre-push` FAIL → `npx cookwright init`; WARN not installed → `npm install`.
- `homes.*` FAIL → `npx cookwright init`. `homes.changelog` weak → ask, then `npx cookwright changelog --adopt` after they keep a copy. `backlog.ids` FAIL → show the duplicate, fix with consent.
- `gate.scripts` FAIL → name the script to fix in `package.json`, with consent. `gate.scripts` PASS with no checks (an Expo scaffold has no test script, stage-1 QA round 2) → say pre-push runs nothing and offer a gate check (`tsc --noEmit`, `expo lint`, their call), written into `gate.checks` with consent.
- `secrets.env` FAIL → say Level 2 replaces it, never open the file, stop. `rules.size` weak → explain, stop. `git` FAIL → stop; init needs a work tree.

Adding a host: edit `hosts` in `cookwright.json` with consent (init never edits an existing config), then `npx cookwright init`; for Codex say to trust the hook with `/hooks`, and again after any rewrite of the file. At the end: print the level line and the `next:` line; name the files init wrote so they commit them by path (`git add <paths>`, never `-A`).

Rules in the skill: never write an env file, never `--no-verify`, never a secret's value in the transcript, no state of its own (doctor is the state), every install outside the repo is the developer's hands.
