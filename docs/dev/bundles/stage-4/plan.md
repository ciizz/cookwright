## 1. Context

The charter's 2026-10-23 amendment: a stack pack ships each engineering rule as a pair, the sentence in a managed section of `AGENTS.md` and the check that measures it; a rule with no measurement is advisory and listed apart. Hooks judge the change (staged files only), the gate ratchets the repo (a rise in violations is drift). Packs are orthogonal to levels, declared in `packs`, and are directories in the package under the one version number.

What exists (*measured* in this planning session, 2026-10-25):

- The config is at version 2; `KNOWN_KEYS.top` in `src/lib/config.mjs:43` refuses any unknown key, so `packs` needs a version bump, and the 2→3 step adds nothing (`packs` defaults to `[]`).
- Doctor's rows are a static frozen table (`src/lib/doctor/registry.mjs:46-65`, 17 rows); `runChecks` maps the table, nothing is derived from config. The whole run shares one 1800 ms budget (`src/lib/budget.mjs`, `BUDGET_MS`), 1500 ms per call.

## 4. Design

### 4.1 Config version 3 and the pack model

- `src/lib/config.mjs`: `CONFIG_VERSION = 3`; `KNOWN_KEYS.top` gains `packs`; `DEFAULTS.packs = []`; `KNOWN_KEYS.pack = ['name', 'rules']`. `validatePacks`: each entry a known name (string) or `{ name, rules? }`, each pack once, `rules` an object whose keys are that pack's rule names and whose values are `false` only (`packs: rule "x" is not a rule of pack expo (known: …)`). Normalisation to `[{ name, off: Set }]` happens in `declaredPacks(config)` (§ registry), after validation, so the validator sees the raw value (residue).
- `src/lib/migrations.mjs`: `2: addPacks`, a pure step writing `packs: []` when the key is absent (outcome `packsAdded`), keeping any present value (`packsKept`). `messages.migrate.outcomes` gains both texts.
- `src/lib/packs/detect.mjs`: `detectPacks(root)` reads `package.json` dependencies and the presence of `supabase/config.toml` (two named reads, no walk); used by `freshConfig` on a fresh config and by the doctor row `packs` (disposition 22), each naming its evidence.
- `schema/cookwright.schema.json`: `version` enum `[1, 2, 3]`; `packs` array of `oneOf` string enum `[expo, supabase]` or object `{ name, rules: { additionalProperties: false, properties per pack rule, each `{ const: false }` } }`; `config.test.mjs` keeps schema and validator in step (one new test for the `rules` property names against each manifest).
- `src/lib/packs/registry.mjs`: `PACKS = Object.freeze({ expo, supabase })` importing each manifest; `declaredPacks(config)`, `activeRules(pack)`, `KNOWN_PACKS`. Imports nothing from messages; the manifests import nothing at all (the cycle rule in `config.mjs`, `levels.mjs` and `budget.mjs` headers).
- `packages/cookwright/packs/<name>/pack.mjs` (the manifest, data plus pure functions): `name`, `version: 1`, `rules: [{ id, sentence, measure: 'eslint' | 'doc-sync' | 'gate' | 'advisory', eslint?: { ruleIds, tag? }, docSync?: { name, code, docs }, gate?: 'types' }]`, `docs: [{ path, template, scope, rules?, code, entries }]` (`entries`: `components` or `migrations`, how an omission row lists what must be documented), `deps: [{ package, reason, install }]`, `eslintExport: 'packs/expo/eslint.cjs'`, `setup: { eslint: 'npx expo lint' }` (the line a SKIP names; the `supabase` pack names `npm install --save-dev eslint`). `package.json` `files` gains `packs`.
- `src/lib/messages.test.mjs` `SCANNED` gains `src/lib/packs`, `src/standards.mjs`, `src/audit.mjs`; the manifests are content modules and go in `EXEMPT`.

### 4.2 The pack section of `AGENTS.md`

- `src/lib/rules/block.mjs` generalised by a `kind` parameter: `beginMarker(kind, version)` renders `<!-- cookwright:begin rules vN -->` (unchanged bytes for the core) or `<!-- cookwright:begin pack expo vN -->`; `beginRe(kind)`; `blockState(text, rendered, kind)`. Existing callers pass the core kind by default; no byte of today's block changes.
- `src/lib/packs/section.mjs`: `renderSection(manifest, off)` builds `## Standards: expo pack`, one sentence per enforced rule with its measurement in parentheses, "(switched off)" after a rule in `off`, then `### Advisory` with the unmeasured sentences. Generated from the manifest, never a hand-kept file (rule 5). A pack's `version` bumps when its sentences change.
- `src/lib/init/packs.mjs`: `packSectionStep` per declared pack mirrors `blockStep` (`init/rules.mjs:29-51`): WROTE when the file is absent, KEPT, UPDATED on stale (splice) or absent (append after the core block), Refusal on malformed. `STEPS` in `init/steps.mjs` gains `everyPack('section')` after `blockStep`, then `everyPack('docs')`, `everyPack('lint')`, `everyPack('deps')`.
- Doctor `pack.<name>.rules`: `blockState` of the section; `current` PASS, `stale` or `absent` FAIL (`run npx cookwright init`), plus WARN when `off` is non-empty (`switched off: size`), the worst status winning and both notes on the line.

### 4.3 Doc contracts and their doc-sync rules

- Templates `packs/expo/templates/design-system.md` and `packs/supabase/templates/data-model.md`: a header stating what the doc is the contract for and how the hook and the omission row read it, then a table with the key column first: `| Primitive | File | Props | Notes |` and `| Migration | Tables and RPCs touched | Summary |`, plus for the data model `## Tables` and `## RPCs` sections with empty `| Table | Purpose | RLS |` and `| RPC | Signature | Purpose |` tables. Written by `fileHome`'s pattern (write if absent, else KEPT) in `packDocsStep`.
- The doc-sync defaults, from the manifest: `{ name: 'expo:design-doc', code: ['src/components/**', 'components/**', ':!**/*.test.*'], docs: ['docs/design-system.md'] }` and `{ name: 'supabase:data-doc', code: ['supabase/migrations/**'], docs: ['docs/data-model.md'] }`. `freshConfig` (`init/config.mjs:52`) appends them when the pack is declared, and `{ name: 'standards', run: 'npx cookwright standards --ratchet' }` to `gate.checks`; an existing config is never edited by init, the setup skill writes both with consent (§4.8).
- Doctor `pack.<name>.docs`: the doc exists (else WARN `docs/design-system.md missing (run npx cookwright init)`); the rule with the pack-owned name is in `hooks.docSync` pointing at the doc (else WARN naming the rule and the setup skill); the omission count: entries listed with one `readdirSync` of each `code` directory and one level below (no recursive walk, the `repo.mjs` rule), basenames without extension, tests and `index` excluded, against the first-column cells of the doc's tables; PASS `12 primitives, 12 documented`, WARN `3 of 12 primitives have no entry in docs/design-system.md: Avatar, Chip, Fab` (disposition 11). Same for migrations by file name. `src/lib/packs/entries.mjs` holds the two listers and the table-cell reader. A `code` directory that does not exist counts 0 (the blank scaffold).

### 4.4 The ESLint exports

- `packs/expo/eslint.cjs` exports a static array of flat-config blocks, each with a `name` (`cookwright/expo/strings` …), all carrying `ignores: ['.claude/**', '.agents/**', '.codex/**', 'node_modules/**', '**/*.test.*', '**/__tests__/**']` (disposition 19). It reads no config (disposition 24); it omits the strings block when `require.resolve('eslint-plugin-i18next')` throws. Blocks only carry `rules` (and `plugins` for i18next); the parser comes from the repo's own config, which is why the pack is spread into it and never run alone.
  - `strings`: files `**/*.{tsx,jsx}`, ignores `**/*.config.*`, `**/locales/**`, `**/theme/**`; `i18next/no-literal-string: ['error', { mode: 'jsx-only', 'jsx-attributes': { exclude: [testID, accessibilityRole, style, source, resizeMode, keyboardType, autoCapitalize, textContentType, returnKeyType, name, href, …] } }]`, the list measured on the origin repo's component tree during QA (c).
  - `tokens`: files `**/components/**/*.{ts,tsx,js,jsx}`, ignores `**/theme/**`, `**/palette.*`, `**/tokens.*`; `no-restricted-syntax` with the origin repo's two selectors (`Literal[value=/^(#hex|rgb…|hsl…)$/]`, `Property[key.name=/^(margin…|padding…)$/] > Literal[raw=/^[0-9]+(\.[0-9]+)?$/]`), each message prefixed `[cookwright expo tokens]` so the counter attributes a `no-restricted-syntax` finding to the pack rule and not to a user's own selector.
  - `size`: `max-lines-per-function: ['error', { max: 150, skipBlankLines: true, skipComments: true, IIFEs: true }]` on `**/*.{tsx,jsx}` and the same rule with `max: 40` on `**/*.{ts,js}` (disposition 13 as amended).
- `packs/supabase/eslint.cjs`: `client`: `no-restricted-imports` with `paths: [{ name: '@supabase/supabase-js', message: '[cookwright supabase client] …' }]` on `**/*.{ts,tsx,js,jsx}`, `off` for `**/services/supabase.*`, `**/lib/supabase.*`, `**/utils/supabase.*`, `supabase/functions/**`. A user's own `no-restricted-imports` block on the same files replaces ours (flat config replaces a rule's options, it does not merge them); the standards guide says so.
- `src/lib/packs/eslint.test.mjs` loads each `.cjs` under node, asserts the blocks, the names, the ignores, that every ESLint id a manifest rule names appears in exactly the blocks of that rule, and the plugin-absent omission (a `require` seam).

### 4.5 The standards runner, the pre-commit check and the ratchet

- `src/lib/packs/standards.mjs` (the one engine, under 40 lines per function):
  - `loadESLint(root)`: `createRequire(root + '/package.json').resolve('eslint')`, `import()` it, require `ESLint.version` ≥ 9 (else `absent: needs ESLint 9 flat config`); `new ESLint({ cwd: root })` so a config root below the top is read; injectable through `io.loadESLint` for tests.
  - `wired(eslint, pack)`: `calculateConfigForFile` on a representative path per rule (`src/components/__cookwright__.tsx`, `src/__cookwright__.ts`) and asserts each active rule's ESLint id is present and not `off`; a rule whose id is missing reads `not wired` (the strings rule with the plugin absent reads `needs eslint-plugin-i18next`), the whole pack reads `not wired` when none is, the note naming the `eslint.config.js` line.
  - `lintAt(eslint, ref, entries)`: for each `{ path, mode }` entry with a regular-file mode, `git show <ref>:<path>` (`:` for the index) piped to `lintText(code, { filePath })`; an absent blob counts 0; a fatal message makes the file `unmeasured` with the message. One 60 s cap on the whole call, as doc-sync caps git.
  - `countBy(results, pack)`: severity-2 messages whose `ruleId` is an active pack rule's id and, for `no-restricted-syntax` and `no-restricted-imports`, whose message starts with the rule's tag, keyed by pack rule name; a rule in `off` is never counted (disposition 8).
  - `matching(entries, pack)`: regular-file entries (mode `100644`/`100755`, never `120000`) under the pack's file globs; `--raw -z` output parsed for mode and path.
- Pre-commit `standards` (`src/lib/hooks/standards.mjs`, registered in `registry.mjs` as `standards: { run, config: true }`, `HOOKS['pre-commit'].checks = ['secrets', 'doc-sync', 'standards']`): no packs → SKIP `no packs declared`; staged entries from `git diff --cached --raw -z --no-renames --diff-filter=ACMR` filtered by `matching`; none → PASS `no staged file under a pack's rules`; ESLint absent → SKIP `skipped, needs eslint, run setup (<manifest setup line>)`; not wired → SKIP with the line; a file unmeasured → SKIP naming the file and ESLint's message (rule 3); otherwise `lintAt(':', entries)`; findings printed above the line as `path:line:col  rule  message`, FAIL `N finding(s) in M staged file(s); fix them, or COOKWRIGHT_SKIP=standards with the reason in the message`; PASS `M staged file(s), 0 findings`. The hook's unknown-skip line test (`hook.test.mjs:276`) changes with `CHECK_NAMES`.
- `src/standards.mjs`, the command `npx cookwright standards [--ratchet] [--base <ref>]`, registered in `cli-main.mjs`:
  - No flag: the repo-wide count per pack rule on HEAD (`git ls-files -s` filtered by `matching`, `lintAt('HEAD', …)`), one line per rule `expo  strings  412`, exit 0; the number an existing app sees first.
  - `--ratchet`: the base per disposition 20; `git diff --raw -z --no-renames <base>..HEAD` filtered by `matching`; none → `0 files under a pack's rules changed since <base>`, exit 0; lint both sides; per rule, `rose` when HEAD > base; any rise → each rule and the files that rose, exit 10; else `standards: expo strings 412 → 410, tokens 3 → 3 (14 files since <base>)`, exit 0. Cannot measure (no pack, no ESLint, not wired, no base resolvable, a file unmeasured) → one line, exit 11.
