## 1. Context

The charter's 2026-10-23 amendment: a stack pack ships each engineering rule as a pair, the sentence in a managed section of `AGENTS.md` and the check that measures it; a rule with no measurement is advisory and listed apart. Hooks judge the change (staged files only), the gate ratchets the repo (a rise in violations is drift). Packs are orthogonal to levels, declared in `packs`, and are directories in the package under the one version number.

What exists (*measured* in this planning session, 2026-10-25):

- The config is at version 2; `KNOWN_KEYS.top` in `src/lib/config.mjs:43` refuses any unknown key, so `packs` needs a version bump. `findRoot` walks up to the work tree's top, so the config root may sit below it; the shims `cd` into it.
- Doctor's rows are a static frozen table (`src/lib/doctor/registry.mjs:46-65`, 17 rows); `runChecks` maps the table, nothing is derived from config. The whole run shares one 1800 ms budget (`src/lib/budget.mjs`, `BUDGET_MS`), 1500 ms per call.
- ESLint on a real app (the origin repo's checkout, ESLint 9.39.4): `eslint --version` 1.1 s; one component file 2.7 s; 40 component files 4.1 s; through the Node API, load plus one `lintText` 1.65 s. **No doctor row can run ESLint.** The kickoff's `pack.<name>.count` row is therefore a command (§2, disposition 3).
- ESLint's Node API is Promise-based throughout (`import()`, `calculateConfigForFile`, `lintText`); `calculateConfigForFile` and `lintText` accept a path with no file at it; the CJS entry resolved through `createRequire` exposes `ESLint` as a named export under `import()`; `overrideConfig` appends blocks after the file's; `lintText`'s `filePath` resolves against ESLint's `cwd`.
- The hook pipeline is synchronous end to end: `verdict()` in `src/lib/hooks/registry.mjs` reads `r.status` straight from `check.run`, `runHook` maps the checks, `src/hook.mjs` computes the exit synchronously; `runBounded` is `spawnSync`.
- `eslint-plugin-i18next` 6.1.4 takes `mode: 'jsx-text-only' | 'jsx-only' | 'all'` (`markupOnly` is the 5.x name the origin repo still passes, ignored by 6.x, so its effective mode is the default `jsx-text-only`). `jsx-only` reports a JSX text child and a non-excluded attribute string; a plain string outside JSX only in `all`. Its message embeds the literal itself (`disallow literal string: …`). The plugin skips the initializer of an all-upper-case identifier (`const X = …`, its constant heuristic), so test components carry real names.
- The managed block (`src/lib/rules/block.mjs`) has one begin-marker shape, `<!-- cookwright:begin rules vN -->`, and a shared end marker; `blockState` takes the first end marker after the begin, so a second managed section with its own begin shape coexists. Init's `preflight` (`src/lib/init/steps.mjs:41-45`) computes every step against the text on disk before any write, and `blockStep` returns whole-file content, so two steps that write the same file clobber each other.
- Hook checks are `run(repo, ctx) → {status, note}`; doc-sync reads the index with `git diff --cached --name-only -z --no-renames --diff-filter=ACMRD -- <specs>` (`docsync.mjs:19`), 60 s cap. Gate checks are shell commands only (`src/lib/bundle/gate.mjs:77`, `run` a string; non-zero exit is fail, 127 included); `runCheck` records only pass or fail and prints, never stores, stdout; `planChecks` is the only place a check reads `skipped`; a gate in which every check skipped is `refused` (`gate.mjs:116`). `KNOWN_KEYS.check = ['name', 'run', 'needs']`.
- git path bases differ by command: `git ls-files` prints paths relative to the cwd, `git diff --raw` and `git show <ref>:<path>` use the work tree's top.
- Init is non-interactive and idempotent, never edits an existing `cookwright.json` (`src/lib/init/config.mjs:74-95`), never runs npm (`repo.mjs` header: no network, no npm). Write-if-absent is `fileHome` in `init/homes.mjs`. `.gitignore` is asked through `probes.ignored` (`git check-ignore`), one path per call. Init writes symbolic links under `.claude/`, `.agents/`, `.codex/`, committed right after init in every repo; `git show :<path>` of a link blob is its target text. Skills are discovered from the explicit `SKILLS` manifest in `src/lib/hosts.mjs:45-48`, never by listing a directory; `skills.test.mjs:37` requires the shipped directories to equal its keys.
- Doctor's `host.rules` reads SKIP when Claude Code is not on PATH (`doctor/claude.mjs:47`), and `hooks.pre-commit`/`hooks.pre-push` read SKIP under a hooks setup managed elsewhere (`doctor/hooks.mjs:186`); all three are in Level 0's `requires`. The fixture (`scripts/ci/fixture.sh:136-137`) asserts `^level 0 declared: complete` and ` 0 FAIL, 0 WARN, `; CI installs gitleaks and nothing else, so `host.rules` SKIPs on every runner.
- The Expo scaffold the fixture pins (`expo-template-blank-typescript@58.0.21`, 13 files) ships **no ESLint and no lint script**. From `@expo/cli@58.1.15`'s tarball: `npx expo lint` installs `eslint@^9.0.0` and `eslint-config-expo`, then copies its static template `static/template/eslint.config.js` verbatim, a CJS file: a comment line pointing at the Expo guide, `const { defineConfig } = require('eslint/config');`, `const expoConfig = require('eslint-config-expo/flat');`, `module.exports = defineConfig([ expoConfig, { ignores: ['dist/*'] }, ]);`. The fixture's `npm install --save-dev <tarball>` installs the scaffold's whole dependency tree too (`typescript` with it), on Node 22.
- `docs-audit.js` takes `{ docs: [{ path, scope, rules? }], invariants? }`, has no generate mode, and nothing builds its args (E-003 open). `bundle-phase.js`'s `header()` points at the rules file by path and hash; the red-team prompt (`redTeam()`, L189) has no stack-specific line.
- The package has no `exports` map, so a deep path `cookwright/packs/expo/eslint.cjs` is requirable; `type: module` means the ESLint export must be `.cjs` to load from the scaffold's CJS config on Node 20.
- This repo's own doc-sync rules: `playbook` ties `src/bundle.mjs`, `src/lib/bundle/*` (tests excluded) and `hosts/claude/workflows/bundle-phase.js` to `docs/playbook.md` or `skills/bundle/SKILL.md`; `setup` ties `skills/setup/SKILL.md` and `agents-block.md` to `docs/guides/*.md`; every code path in this repo lives under `packages/cookwright/`.

## 2. Decisions

Taken by the developer on 2026-10-25 (kickoff): two packs, `expo` and `supabase`; the ratchet compares the files the branch changed; `eslint-plugin-i18next` is the `expo` pack's dependency, installed into the user's repo with consent, never a dependency of `cookwright`.

Dispositions by the Judgment rules, recorded with `bundle decide` at kickoff:

1. Rule 3 (claim what was measured): the pack names its rules by what they measure, `strings`, `tokens`, `size`, `design-doc` (expo); `client`, `data-doc`, `types` (supabase); advisory `components-first`, `visual-contract`, `reuse-first`. The kickoff's example `{ "rules": { "max-lines": false } }` used an ESLint rule id; one ESLint id (`no-restricted-syntax`) carries two pack rules and a doc-sync rule has no ESLint id, so the switch is per pack rule: `{ "name": "expo", "rules": { "size": false } }`.
2. Rule 5 (derived state is never stored) and rule 3: the ratchet lints the base version of each changed file from `git show <base>:<path>` through ESLint's `lintText`, and the HEAD version from `git show HEAD:<path>`, so both sides are commits, never the tree. A file added or deleted on the branch (status A or D in the raw diff) counts 0 on its absent side. Nothing is written.
3. Rule 3: `pack.<name>.count` is not a doctor row. Doctor's budget is 1800 ms and ESLint needs 1.1 s to start (§1); a row that always reads SKIP claims nothing. The repo-wide count is `npx cookwright standards`, printed per rule; the gate runs `npx cookwright standards --ratchet`. The kickoff allowed the SKIP; this removes the row instead, so B-013's "complete" is not defeated by a standing SKIP.
4. Rule 1 (a harness problem never blocks) and rule 3: a gate check may say it skipped after it started, when the check opts in: a `gate.checks` entry with `skipExit: 11` has that exit recorded as `skipped` with its first stdout line (disposition 36). Any other non-zero exit, and exit 11 on a check without `skipExit`, stays a fail. `noCheckRan` carries the skip lines, so a fresh app whose only gate checks skipped reads why.
5. Rule 9 (every dependency asked first) and the no-npm rule of init: init never installs `eslint-plugin-i18next`. It reports `skipped  eslint-plugin-i18next  needs npm install --save-dev eslint-plugin-i18next (the strings rule)`, doctor's `pack.expo.lint` WARNs with the same line, and the setup skill runs the install with consent. The strings rule reads `skipped, needs …` on the hook's line until then, never FAIL (disposition 37). The kickoff said "init installs it with consent"; init has no consent surface, the skill does.
6. Rule 4 (imported, never copied): the ESLint config is `require('cookwright/packs/<name>/eslint.cjs')`, spread into the repo's `eslint.config.js`. Init writes one line per declared pack when the file is byte-equal to Expo's template (§1), inserting `...require('cookwright/packs/expo/eslint.cjs'),` and `...require('cookwright/packs/supabase/eslint.cjs'),` after `expoConfig,`, with `--dry-run` as the preview; any other file is `skipped` naming the lines, and doctor WARNs until the config names the exports. One step transforms the file once for all declared packs (disposition 27).
7. Rule 4 and the kickoff's E-039 path: the pack's two doc-sync rules are config, not logic, so they are written into `cookwright.json` with a pack-owned name (`expo:design-doc`, `supabase:data-doc`): by init into a fresh config, by the setup skill with consent into an existing one. Doctor's `pack.<name>.docs` reads a missing rule as WARN naming it.
8. ## 4. Design

### 4.1 Config version 3 and the pack model

- `src/lib/config.mjs`: `CONFIG_VERSION = 3`; `KNOWN_KEYS.top` gains `packs`; `DEFAULTS.packs = []`; `KNOWN_KEYS.pack = ['name', 'rules']`; `KNOWN_KEYS.check` gains `skipExit` (disposition 36). `validatePacks`: each entry a known name (string) or `{ name, rules? }`, each pack once, `rules` an object whose keys are that pack's rule names and whose values are `false` only (`packs: rule "x" is not a rule of pack expo (known: …)`). Normalisation to `[{ name, off: Set }]` happens in `declaredPacks(config)`, after validation, so the validator sees the raw value.
- `src/lib/migrations.mjs`: `2: addPacks`, a pure step writing `packs: []` when the key is absent (outcome `packsAdded`), keeping any present value (`packsKept`). `messages.migrate.outcomes` gains both texts.
- `src/lib/packs/detect.mjs`: `detectPacks(root)` reads `package.json` dependencies and the presence of `supabase/config.toml` (two named reads, no walk); used by `freshConfig` on a fresh config and by the doctor row `packs` (disposition 22), each naming its evidence.
- `schema/cookwright.schema.json`: `version` enum `[1, 2, 3]`; `packs` array of `oneOf` string enum `[expo, supabase]` or object `{ name, rules: { additionalProperties: false, properties per pack rule, each `{ const: false }` } }`; `gate.checks.items` gains `skipExit` (integer, 1–255); `config.test.mjs` keeps schema and validator in step (one new test for the `rules` property names against each manifest).
- `src/lib/packs/registry.mjs`: `PACKS = Object.freeze({ expo, supabase })` importing each manifest; `declaredPacks(config)`, `activeRules(pack)`, `KNOWN_PACKS`. Imports nothing from messages; the manifests import nothing at all (the cycle rule in `config.mjs`, `levels.mjs` and `budget.mjs` headers).
- `packages/cookwright/packs/<name>/pack.mjs` (the manifest, data plus pure functions): `name`, `version: 1`, `rules: [{ id, sentence, measure: 'eslint' | 'doc-sync' | 'gate' | 'advisory', eslint?: { ruleIds, tag?, options }, docSync?: { name, code, docs }, gate?: { name, run } }]` (`options`: what `wired` compares, disposition 29), `docs: [{ path, template, scope, rules?, code, entries }]` (`entries`: `components` or `migrations`, disposition 33), `deps: [{ package, reason, install }]`, `eslintExport: 'packs/expo/eslint.cjs'`, `setup: { eslint: 'npx expo lint' }` (the line a skip names; the `supabase` pack names `npm install --save-dev eslint`), `messages`: the one-line text per rule the hook prints (disposition 41). `package.json` `files` gains `packs`.
- `src/lib/messages.test.mjs` `SCANNED` gains `src/lib/packs`, `src/standards.mjs`, `src/audit.mjs`, `src/packs.mjs`; the manifests are content modules and go in `EXEMPT`.

### 4.2 The pack section of `AGENTS.md`

- `src/lib/rules/block.mjs` generalised by a `kind` parameter: `beginMarker(kind, version)` renders `<!-- cookwright:begin rules vN -->` (unchanged bytes for the core) or `<!-- cookwright:begin pack expo vN -->`; `beginRe(kind)`; `blockState(text, rendered, kind)`. Existing callers pass the core kind by default; no byte of today's block changes.
- `src/lib/packs/section.mjs`: `renderSection(manifest, off)` builds `## Standards: expo pack`, one sentence per enforced rule with its measurement in parentheses, "(switched off)" after a rule in `off`, then `### Advisory` with the unmeasured sentences. Generated from the manifest, never a hand-kept file (rule 5). A pack's `version` bumps when its sentences change.
- `src/lib/init/rules.mjs`: `rulesFileStep` (disposition 27) replaces `blockStep`: it reads `AGENTS.md` once, applies the core block's state machine (WROTE, KEPT, UPDATED on stale by splice, UPDATED on absent by append, Refusal on malformed) and then each declared pack's section in order, appended after the core block when absent, spliced when stale, and returns one row per block and one write of the composed file. `STEPS` in `init/steps.mjs`: `rulesFileStep` where `blockStep` was, then `packDocsStep`, `eslintConfigStep`, `packDepsStep` (each iterating the declared packs internally, writing distinct files or no file).
- Doctor `pack.<name>.rules`: `blockState` of the section; `current` PASS, `stale` or `absent` FAIL (`run npx cookwright init`), plus WARN when `off` is non-empty (`switched off: size`), the worst status winning and both notes on the line.

### 4.4 The ESLint exports

- `packs/expo/eslint.cjs` exports a static array of flat-config blocks, each with a `name` (`cookwright/expo/strings` …), all carrying `ignores: ['.claude/**', '.agents/**', '.codex/**', 'node_modules/**', '**/*.test.*', '**/__tests__/**']` (disposition 19). It reads no config (disposition 24); it omits the strings block when `require.resolve('eslint-plugin-i18next')` throws. Blocks only carry `rules` (and `plugins` for i18next); the parser comes from the repo's own config, which is why the pack is spread into it and never run alone.
  - `strings`: files `**/*.{tsx,jsx}`, ignores `**/*.config.*`, `**/locales/**`, `**/theme/**`; `i18next/no-literal-string: ['error', { mode: 'jsx-only', 'jsx-attributes': { exclude: [testID, accessibilityRole, style, source, resizeMode, keyboardType, autoCapitalize, textContentType, returnKeyType, name, href, …] } }]`, the exclude list measured in s4 against the origin repo's component tree (disposition 44).
  - `tokens`: files `**/components/**/*.{ts,tsx,js,jsx}`, ignores `**/theme/**`, `**/palette.*`, `**/tokens.*`; `no-restricted-syntax` with the origin repo's two selectors (`Literal[value=/^(#hex|rgb…|hsl…)$/]`, `Property[key.name=/^(margin…|padding…)$/] > Literal[raw=/^[0-9]+(\.[0-9]+)?$/]`), each message prefixed `[cookwright expo tokens]` so the counter attributes a `no-restricted-syntax` finding to the pack rule and not to a user's own selector.
  - `size`: `max-lines-per-function: ['error', { max: 150, skipBlankLines: true, skipComments: true, IIFEs: true }]` on `**/*.{tsx,jsx}` and the same rule with `max: 40` on `**/*.{ts,js}` (disposition 13).
- `packs/supabase/eslint.cjs`: `client`: one block, files `**/*.{ts,tsx,js,jsx}`, `ignores: ['**/services/supabase.*', '**/lib/supabase.*', '**/utils/supabase.*', 'supabase/functions/**', …]` (disposition 29), `no-restricted-imports` with `paths: [{ name: '@supabase/supabase-js', message: '[cookwright supabase client] …' }]`. A user's own `no-restricted-imports` block on the same files replaces ours; `wired` reads that as overridden and the guide says so.
- `src/lib/packs/eslint.test.mjs` loads each `.cjs` under node, asserts the blocks, the names, the ignores, that every ESLint id a manifest rule names appears in exactly the blocks of that rule with the manifest's `options`, and the plugin-absent omission (a `require` seam).

### 4.5 The standards engine, the command, the pre-commit check and the ratchet

- `src/lib/packs/standards.mjs` (the async engine, under 40 lines per function; disposition 28's path base throughout):
  - `loadESLint(root)`: `createRequire(root + '/package.json').resolve('eslint')`, `import()` it, require `ESLint.version` ≥ 9 (else `absent: needs ESLint 9 flat config`); `new ESLint({ cwd: root })` (disposition 47 replaces disposition 42's override); injectable through `io.loadESLint`.
  - `wired(eslint, pack)`: `calculateConfigForFile` on a representative absolute path per rule and the comparison of disposition 29; returns per rule `measured`, `not wired`, `overridden`, or `needs <dep>`.
  - `entries(top, root, source)`: the raw entries (`mode`, `status`, `topRel`, `baseTopRel` for a rename) from `git diff --cached --raw -z -M --diff-filter=ACMRD -- <rootRel>` (staged), `git diff --raw -z -M <base>..HEAD -- <rootRel>` (ratchet) or `git ls-files -s -- <rootRel>` from the top (count); `matching(entries, pack)` keeps regular files under the pack's globs.
  - `lintAt(eslint, ref, entries)`: `git show <ref>:<topRel>` (`:` for the index) piped to `lintText(code, { filePath: join(top, headTopRel) })`, the HEAD path for a rename's base side (disposition 47); an added file's base side counts 0; deleted files are not linted; any other `git show` failure, a fatal message or a rejected `lintText` makes the file `unmeasured` with the message.
  - `countBy(results, pack)`: severity-2 messages whose `ruleId` is an active pack rule's id and, for `no-restricted-syntax` and `no-restricted-imports`, whose message starts with the rule's tag, keyed by pack rule name and file; a rule in `off` or not `measured` is never counted.
  - `render(findings)`: `rootRel:line:col  <pack rule>  <manifest message>` (disposition 41).
- `src/standards.mjs`, the command `npx cookwright standards [--staged | --ratchet [--base <ref>] | --types]`, registered in `cli-main.mjs`, exit 0 PASS, 10 FAIL, 11 cannot measure (one line naming why), every line through `messages.standards`:
  - No flag: the repo-wide count per pack rule on HEAD, one line per rule `expo  strings  412`, exit 0; the number an existing app sees first.
  - `--staged` (the hook's child, disposition 26): disposition 31's per-file ratchet over the staged entries; exit 10 when any file's count rose for a rule, its findings printed first; exit 0 `M staged file(s), no rise` with disposition 37's tail; exit 11 for no pack, no matching file is exit 0 `no staged file under a pack's rules`, ESLint absent, every rule not wired, a file unmeasured.
  - `--ratchet`: the base per disposition 20 and 39; per rule, `rose` when HEAD > base over the changed files; exit 10 naming each rule and the files that rose; exit 0 with the first line `standards: expo strings 412 → 410, tokens 3 → 3; <unmeasured rules per disposition 37>; <n> deleted file(s) not counted (14 files since <base>)`, the line the gate records (disposition 45); no matching change is exit 0 `0 files under a pack's rules changed since <base>`.
  - `--types` (disposition 40): the Supabase types measure alone.
- `src/lib/hooks/standards.mjs`, registered in `registry.mjs` as `standards: { run, config: true }`, `HOOKS['pre-commit'].checks = ['secrets', 'doc-sync', 'standards']`: no packs → SKIP `no packs declared` without spawning; otherwise `spawnSync(process.execPath, [bin, 'standards', '--staged'], { cwd: root, env, timeout: 60_000, killSignal: 'SIGKILL' })` through `io.spawn`; prints the child's stdout above its line; exit 0 → PASS with the child's last line, 10 → FAIL `… fix them, or COOKWRIGHT_SKIP=standards with the reason in the message`, 11 → SKIP with the child's line, a timeout → SKIP `skipped, standards took longer than 60 s`, anything else → SKIP `could not run`. The hook's unknown-skip line test (`hook.test.mjs:276`) changes with `CHECK_NAMES`.
- `src/lib/hooks/push.mjs`: `pushContext` returns `{ base }` per disposition 39; `gateEnv` adds `COOKWRIGHT_PUSH_BASE` when present.
- `gate.mjs` `runCheck`: a check with `skipExit` records its first stdout line as `note` on every outcome (disposition 45), and a status equal to `skipExit` → `result: 'skipped'` (dispositions 4 and 36); `recordGate` stores the note; `noCheckRan` lists each skipped check's note; `check.mjs` reads a skipped check, or a passed check whose note names a skipped rule, as WARN naming it; the closeout's gate table prints the note. The texts live in `lib/bundle/messages.mjs` beside `noCheckRan`; the playbook's "The gate's checks" section states the convention (disposition 48).
