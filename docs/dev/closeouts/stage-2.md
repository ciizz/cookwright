## What shipped

**`cookwright hook pre-commit|pre-push`** (`src/hook.mjs`, library `src/lib/hooks/`), what the git shims call. pre-commit runs `secrets` (gitleaks over the staged diff, `--exit-code 3` separating a finding from a failure to run, spawned at the work tree's top with its output streamed and redacted) and `doc-sync` (the rules of `hooks.docSync`, matched by git's own pathspec machinery through `git diff --cached`, never `ls-files`, which drops a leading-star exclude). pre-push runs `gate` (the repo's `gate.checks` through the bundle gate's own runner, git's hook variables stripped from the commands' environment, the elapsed time on the line) and `changelog`. The exit contract is the charter's rule 1 before it was written: exit 10 when, and only when, a check FAILed; everything about the harness itself (no config, an invalid one, a tool absent, a check that threw or timed out) is one SKIP line on that check and never changes another check's FAIL, and `secrets` runs without any config. `COOKWRIGHT_SKIP=<check,…>` is the per-check escape, named on its line. pre-push judges the working tree: a dirty tree makes both checks SKIP with the count of uncommitted files, a pushed ref that is not HEAD is named as not tested, an annotated tag on HEAD counts as HEAD (every pushed sha is peeled), and a push of HEAD with other refs names what it tested and what it did not.

**The shims** (`src/lib/hooks/shims.mjs`), eight lines each, written into the user's `.githooks/` with mode 0755: node absent and package absent each print one line and exit 0; the call's exit code is mapped, 10 to 1 for git and anything else to a crashed line and exit 0, so a module that does not load can never block a commit. When `cookwright.json` sits below the work tree's top, the shim enters the config root first. "Calls cookwright" accepts only the forms in which a finding's exit code reaches git (`exec`, `|| exit 1`, `|| exit $?`, or the call as the last line); `|| true` reads as not a call.

**init step 8** (`src/lib/init/hooks.mjs`): `core.hooksPath` set to `.githooks` in the local config, the two shims written at the work tree's top, a shim that calls cookwright but is not executable made so. A foreign setup (a hooksPath elsewhere or from a scope other than local, a user's hook in git's hooks directory, a `.githooks/` file that is not cookwright's) skips all three rows with the reason and writes nothing. The git write runs after the file writes, so the path is never activated before the shims exist. `files.mjs` grew a `mode` on a write and a `{ git: [args] }` write.

**doctor**: five checks join the registry and Level 0's `requires`: `hooks.path` (PASS local `.githooks`; WARN for a chosen foreign setup, the reason named and never a machine path; FAIL unset), `hooks.pre-commit` and `hooks.pre-push` (the file calls cookwright and is executable; WARN when the package is not installed where the shim runs; SKIP when hooks are managed elsewhere), `tools.gitleaks` (on PATH and one bounded dry invocation exits 0 or 3; FAIL names a malformed config; SKIP needs gitleaks), `gate.scripts` (every npm script a gate check names exists). `homes.changelog` reads the generated marker and WARNs on a hand-kept file. Sixteen checks; one shared reader (`hooksSetup`) gives init and doctor the same foreign verdicts; the hooksPath scope comes from `git config --show-scope`, with a fallback for a git older than 2.26.

**`cookwright changelog [--check | --unreleased | --adopt]`** (`src/changelog.mjs`, library `src/lib/changelog/`): the changelog generated from the strict `vX.Y.Z` tags merged into HEAD, in version order, a release's commits being those reachable from its tag and from no lower version, so a merged maintenance release is listed once; conventional subjects sorted into Features, Fixes and Performance with `**BREAKING**` and the scope, everything else counted as internal; an annotated tag's body read as `key: value` lines (`released` in the heading, `note` as a blockquote, any other key rendered as `**Key.** value`), the signature cut off by git's own `%(contents:signature)`, a lightweight tag carrying no metadata; the tag listing's `%1f` delimiter, not the pretty format's `%x1f`. The header is the template init seeds, so a repo with no tag renders the template byte for byte and passes `--check` from before its first commit, an unborn HEAD included. The default run refuses a changelog without the generated marker unless `--adopt`; writes refuse links as init does; `--check` compares LF-normalised and exits 1 on missing, unmarked or stale, 2 on a refusal; `--unreleased` prints what no tag holds. The schema's `paths.changelog` description follows.

**Config**: `hooks.docSync`, a list of `{ name, code, docs }` rules of git pathspecs, with static validation of pathspec magic so a typo is a config FAIL at session start; the loader now refuses a non-object `hooks`, `gate` or `paths` instead of defaulting it (B-006). `gitRun` takes a cap, `runBounded` a 64 MiB buffer.

**The managed rules block, v2** (`RULES_VERSION = 2`): user-visible changes are conventional commit subjects and the changelog is generated; the doc-sync paragraph names the hook and the `COOKWRIGHT_SKIP=doc-sync` escape with its reason in the commit message; a Git hooks section. This repo's block was the first refreshed in the wild (`updated`, the text outside the markers byte-identical).

**The charter** gained its second dated amendment, the developer's nine Judgment rules, appended verbatim by the orchestrator after fix:hooks (s3, the session the decision named, had already closed); from that point every disposition cites the rule it rests on, and the whole-branch review judged the branch against them.
