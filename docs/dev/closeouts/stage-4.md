## What shipped

**The pack model** (s1). Config version 3: `packs`, an array of names or `{ name, rules }` objects where a rule is switched off with `false`; a 2→3 migration that writes `packs: []` and changes nothing else; `gate.checks[].skipExit`. `packages/cookwright/packs/<name>/pack.mjs` is each pack's manifest (its rules with their sentences and measurements, its contract doc with the audit scope, its dependency, its detection), `src/lib/packs/registry.mjs` reads them, and `src/lib/rules/block.mjs` gained block kinds so a pack's section (`<!-- cookwright:begin pack expo v1 -->`) sits beside the core block, whose bytes did not change. The section is rendered from the manifest: enforced rules with the check that measures them, "(switched off)" after a switched-off rule, an `### Advisory` heading for the three unmeasured rules of the `expo` pack.

**Init and the fixture** (s2, fix:model). `AGENTS.md` is composed in one pass from one text, the core block then every declared pack's section, one row per block and one write, after plan-review round 1 showed that two steps writing one file clobber each other through init's preflight (disposition 27); review:model found the other collision, a pack's contract doc path equal to a configured state home, and preflight now refuses two writes to one path. A fresh config declares the packs init detects (`expo` from `package.json`, `supabase` from `supabase/config.toml` or the client dependency) or takes `--packs`; an existing config never gets a pack from init or migrate, by the developer's amendment, and doctor's `packs` row WARNs when no pack is declared and the tree shows a stack (a partly declared tree is E-042). Init writes each pack's contract doc from its template when absent, spreads each pack's ESLint export into Expo's `eslint.config.js` when the file is byte-equal to the template `npx expo lint` writes (measured from `@expo/cli@58.1.15`'s tarball), names the lines to add by hand otherwise, and names the plugin's install line without running npm. The fixture installs `eslint`, `eslint-config-expo` and `eslint-plugin-i18next` at pinned versions (9.39.5, 58.0.4, 6.1.5, bumped by hand) and supplies Expo's config template and `supabase init`'s files from the overlay; it asserts the pack rows, a violating component refused by the hook and the corrected one accepted, a Supabase client import counted `0 → 1`, the ratchet's exit 11 on `main` with no upstream, the types measure's skip, and `audit args` printing both docs.

**The measurements** (s4, s5, fix:measure, fix:whole). The engine (`src/lib/packs/standards.mjs`) loads the repo's own ESLint 9 through its Node API and measures a pack rule only where it is wired as the pack set it: severity `error` and exactly the pack's options at every covered file, read from the effective config (`calculateConfigForFile`) so a later block that changes an option, or a config that ignores the file, reads overridden or ignored and never a measured zero. The pre-commit `standards` check runs the engine as a child process (`standards --staged`, a 60 s kill timeout, since the hook pipeline is synchronous and ESLint's API is not) and is a per-file ratchet: a touched legacy file fails the commit only when one of the pack's counts rose in that file. `npx cookwright standards --ratchet` lints both sides of the files the branch changed from blobs, never the tree, against a base resolved in order (`--base`, the pushed ref's remote commit from pre-push, the base branch's upstream when HEAD is on it, else the merge-base), each candidate verified; `--types` regenerates the Supabase types from the local stack for one accepted script shape and skips when the stack differs from HEAD's migrations in either direction. A gate check opts into exit 11 as "skipped" with `skipExit`, its first stdout line recorded as the note on every outcome and scrubbed of the repo and home paths; a partly measured ratchet reads WARN at landing. Findings are printed as `path:line:col  <pack rule>  <the pack's own message>`, never ESLint's text, which for the strings rule embeds the literal. A tagged finding is attributed wherever ESLint puts the tag, after review:measure found the Supabase client rule never counted under real ESLint (its message starts with ESLint's own sentence) while the fake had hidden it.

**The surface** (s6, s7, fix:surface). The setup skill gained recipe rows for every pack row and, with consent, the end pass the kickoff asked for: the detected packs, the plugin, the config lines (after reading the effective config and asking when a block of the app's own sets one of the pack's rule ids), the doc-sync rules and gate entries from `npx cookwright packs rules`, and the fill of a contract doc on its own branch, committed before the docs-audit verifies it there. The guides: a new standards guide, getting-started, hooks-and-escapes and updating for the packs; README's "Standards for your stack, each one measured".

**This repo eats its own cooking** (s7, fix:surface, fix:whole): `cookwright.json` at version 3 (`packs: []`, this is a Node package), the `setup` doc-sync rule covering the packs and their modules, two new rules tying the audit, standards and pack modules to the standards guide, the `docs-audit` pointer written by init; doctor at close `19 checks — 19 PASS`, `level 0 declared: complete`.

## Deviations from the plan, recorded as decisions

- `pack.<name>.count` is a command, not a doctor row (disposition 3, measured).
- The hook runs the engine as a child process and is a per-file ratchet (dispositions 26 and 31); the plan had an in-process engine and an absolute hook, the latter against the charter's sentence.
- Independent measurements are independent gate checks with an opt-in `skipExit`, the first line recorded on every outcome (dispositions 30, 36, 45); the plan's exit 11 for every check would have failed a user's own check.
- The size rule is `max-lines-per-function` only, 150 on `.tsx`/`.jsx` and 40 on `.ts`/`.js` (the developer's amendment 21); existing configs never get a pack (amendment 22); the fixture pins its ESLint versions (23); the ESLint export reads no config (24); no root devDependency for ESLint (25).
- The pack-owned doc-sync rule must match the manifest exactly, a wider rule going under the user's own name (fix:model); a switched-off rule is honoured by the hook, the ratchet and doctor, and a rule's options must equal the pack's exactly in both measurement phases (QA runs 3 to 5, after a looser reading let an added i18next key switch detection off while reading measured).
- The contract-doc reader implements a declared grammar, not CommonMark (E-052), after five QA runs of Markdown cases (runs 1 to 5, a sixth noted on E-052); E-053 holds the array-valued rules' subset match.
- Disposition 18 amended by measurement: the scaffold's `CLAUDE.md` import keeps `host.rules` green without Claude Code, so the fixture's level line depends on gitleaks alone.
