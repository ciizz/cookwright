## What stage 5 was for

The charter's Secrets decision: never a plaintext env file, not even as a fallback; a secret injected into one child process with target proof; three backends at launch, 1Password `op`, the macOS Keychain and `age` with a passphrase-protected identity as the free universal path; no backend configured means Level 2 is off. The kickoff of 2026-10-26 named the command, the config, the proof kinds, the backends, the doctor rows and the agent's rules, and took three decisions: secrets sit beside the levels, not on the ladder; the `age` ciphertext and recipients are tracked; a target without a proof reads WARN and `unproved`. The origin repo's credential contract was read for its shapes (the anchored Supabase proof, the near-miss table, the recipients-file rule, the stated residual) and never run.

## What shipped

**The config** (s1). Version 4: `secrets { backend, id, targets }`, each target `{ names, proof }`; a proof kind is `host` or a declared pack's kind, validated by the loader as it validates pack rules; `secrets.id` required with the keychain backend; an empty `targets` valid (amendment 44). The 3→4 migration changes only the version (`secretsNone`, `secretsKept`); this repo migrated in s1.

**The proofs** (s1, fix:model). The core `host` kind and the `supabase` kind in the pack manifest, lifted from the origin's anchored check: a project URL `https://<ref>.supabase.co`; a database URL naming the ref as the pooler user `<role>.<ref>` on one `*.pooler.supabase.com` host, or as the direct host `db.<ref>.supabase.co`. Both kinds refuse a postgres value whose query string carries a libpq connection parameter, whose user part holds an unencoded `/ ? # @`, or whose host part lists more than one host (review:model's P1: libpq connects to the first host of a comma list, so a pooler anchor on the last one proved nothing).

**`npx cookwright run <target> -- <command…>`** (s2, fix:engine, fix:whole). Resolves the target's values into memory through its backend, proves them, checks the child's argv for any value (resolved or a stale inherited one) and for a non-loopback URL with a password, builds the child's environment (declared, ambient, libpq and backend control names dropped, the values added), prints one banner on stderr, spawns the one child with stdout and stderr through a byte redactor, and exits with the child's status, 127 when it cannot start, 128+n on a signal, 125 for every refusal before the spawn (answer 1 at plan review). The redactor works on bytes, so binary output comes through byte-identical, and holds back only a tail that is a needle's prefix.

**The backends** (s2, s3). `age`: `secrets init` (consent, a binary passphrase-protected identity outside every git work tree judged by the real path of its directory and of the file itself, a second repo enrolled with the same identity) and `secrets set` (the value from a hidden prompt or `--stdin`, never an argument; the recipients file tracked and equal to HEAD before anything is encrypted). `keychain`: items under `cookwright/<id>/<target>`, written through `security -i` on stdin (the prompt of `security add-generic-password` goes through `getpass(3)`, which keeps 128 characters: inferred from the binary's symbols and the man page, not measured with a long value) and read back by hash, read with `-g`. `1password`: a committed template of `op://` references only, handed to `op inject -i` in a private temporary file (QA round 2's P1, below).

**Doctor** (s3, fix:surface, fix:whole). Three rows registered at the end of `CHECKS`, after `packs` (so they print before a declared pack's own rows): `secrets.backend`, `secrets.targets`, `secrets.carriers` (E-015: `.envrc`, an exported declared or ambient name, a line setting one in a shell rc file). 22 static rows; on this repo `22 checks — 22 PASS`.

**The surface** (s4, s5, fix:surface). The managed block v4 gives the agent the run rules (run only with a target the developer named; hand `run` to the developer with a passphrase-protected identity; never export, pass or print a value; never read a value from the backend directly; `secrets init` and `set` are the developer's). The setup skill gained the three recipe tables and a secrets pass. `docs/guides/secrets.md` is new; getting-started, updating, hooks-and-escapes and README name the secrets surface. This repo's `cookwright.json` gained a fifth doc-sync rule, `secrets`.

## Deviations from the plan, recorded as decisions

- The modules live in `src/lib/secret/` (singular): the developer's agent settings deny reading any `secrets/` path, so every tool session would have been refused the plan's path.
- The keychain write goes through `security -i` with a read-back check, not `security`'s own prompt (decision 48 superseded on the `getpass(3)` limit, disposition 60; `security -i` itself measured); keychain `resolve` reads with `-g`, not `-w`.
- An empty `age -p` passphrase is not refused: age prints the one it generates on the terminal it opened, which cookwright cannot see without handling the passphrase (disposition 10 amended by measurement).
- The inherited-needle exemption is narrowed to the local stack's public default (a loopback URL whose password is `postgres`, or `PGPASSWORD=postgres`), after the orchestrator's earlier, wider reading of amendment 43 was found by review:engine.
- The 1Password backend feeds `op inject` a private file of references, not stdin (QA round 2).
- The developer gave no different ruling on the three open points (the narrowed exemption, the keychain write, the empty passphrase); they stand as built, recorded as the orchestrator's reading of that silence.
