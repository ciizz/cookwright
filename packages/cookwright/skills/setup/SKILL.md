# setup — Level 0

**Doctor is the state; this skill keeps none of its own.** Every decision below is made from a doctor readout taken after the last thing you changed. The logic lives in the CLI (`npx cookwright …`); this skill only says which command answers which line.

It is reached once `npx cookwright init` has run (init writes the pointer that makes this skill visible), so a repo without `cookwright.json` starts from the README's first run, not here.

## Rules

- Never write a plaintext env file (`.env`, `.env.*`), not as a fallback and not for a test, and never open one.
- Never put a secret's value in the transcript, a doc, a commit or a log. Name the secret instead.
- Never `git commit --no-verify`, never `git add -A`.
- An install outside the repo (`brew`, `apt`, `winget`, a host update) is the developer's hands: give the exact command, never run it. A change to `package.json`'s dependencies is asked for first.
- "With consent" below means: say what you will change and why, and wait for a yes.

## The loop

1. Run `npx cookwright doctor` and read the whole readout: one line per check (`STATUS  check  note`), then the counts, the level line and the `next:` line.
2. Take the first line that is not PASS and that you have not already stopped at in this run. Find it in the recipe below by its check, its status and its note.
3. Apply exactly one remedy, show the command's own output lines, then go back to 1. Never act on a readout taken before the last remedy.
4. **A remedy that does not clear its line.** When the remedy refuses (it exits non-zero, or prints an `init: …` or `migrate: …` refusal), when the next readout shows the line as it was, or when the developer declines it, show the command's output and the line, and **stop at** that line: never apply the same remedy to the same line twice in a run. One exception: a refusal that names a file to fix by hand (`… is not valid JSON (…); fix it by hand, then rerun`, `… is not the shape … reads …; fix it by hand, then rerun`, `… is a symbolic link and init does not write through one …`, `… exists and is not a file; move it aside, then rerun`) makes that fix the next remedy: show the refusal, make the fix it names with consent, then go back to 1.
5. Stop when every line is PASS, or when every line left is one you stopped at: explain each of those in a sentence and take no action on it. Then do what "At the end" says, which covers the PASS lines that carry advice.

A line the recipe does not name: show it, say this skill has no recipe for it, and **end** the walkthrough there. Never improvise a remedy. A line that **ends** the walkthrough also ends it.

With several hosts, a host check's note is one part per host (`claude: …; codex: …`); take each part as its own line.

## Recipe

### `config`

| status | note | remedy |
|---|---|---|
| WARN | `valid at version N after migrating from M in memory; run npx cookwright migrate to write it` | `npx cookwright migrate` |
| FAIL | `version N is newer than this cookwright's M: update cookwright …` | ask first, then `npm install cookwright@latest` |
| FAIL | any other line (the file is invalid) | show the line; fix the key it names in `cookwright.json` by hand, with consent |

Doctor refusing with `no cookwright.json at or above …` → `npx cookwright init`. While `config` FAILs, the other checks read SKIP `config invalid`: they follow from it, so fix `config` first.

### `git`

| status | note | remedy |
|---|---|---|
| FAIL | `not a git work tree` | **end**: init and every hook need a git repo; `git init` is the developer's call |
| WARN | `baseBranch X does not exist` | with consent, create the branch, or set `baseBranch` in `cookwright.json` to the branch they merge into |
| SKIP | `skipped, needs git, run setup` (on any check) | **end**: git is not on PATH; give the install command for their platform |

### State homes

| check | status | note | remedy |
|---|---|---|---|
| `homes.backlog`, `homes.closeouts`, `homes.changelog` | FAIL | `… missing (run npx cookwright init)` | `npx cookwright init` |
| `homes.backlog` | WARN | `… lacks "## …"` | with consent, add the named headings to the backlog |
| `homes.changelog` | WARN | `not generated by cookwright; … --adopt replaces the file` | ask; once they have kept a copy of what they want from it, `npx cookwright changelog --adopt` |
| `backlog.ids` | WARN | `duplicate id(s): …` | show the duplicates; with consent, give the later line the next free id (ids are never reused) |
| `backlog.ids` | SKIP | `no backlog file` | follows `homes.backlog` |

### Rules

| check | status | note | remedy |
|---|---|---|---|
| `rules.block` | FAIL | `no AGENTS.md`, `has no managed block`, `the managed block is stale` | `npx cookwright init` |
| `rules.block` | WARN | `block vN is newer than this cookwright` | ask first, then `npm install cookwright@latest` |
| `rules.block` | FAIL | `the managed block is malformed (…)` | show the reason; with consent, repair the markers by hand (init refuses a malformed block too) |
| `rules.size` | WARN | `… KB (cap 60 KB)` or `line … is … chars` | **stop at**: explain that a host may truncate a rules file past the cap; moving text out is theirs |
| `host.rules`, Claude Code | FAIL | `AGENTS.md is shadowed by …` | with consent, `npx cookwright init`, which writes or prepends `@AGENTS.md` in the root `CLAUDE.md`; offer the README's "Already have a `CLAUDE.md`?" paragraph as the cleaner way |
| `host.rules`, Claude Code | FAIL | `claude X reads only CLAUDE.md …` | `npx cookwright init` writes the import; updating Claude Code is the other way, the developer's hands |
| `host.rules`, Claude Code | SKIP | `skipped, needs claude, run setup …` | **stop at**: `claude` is not on PATH here, so its version is unverified |
| `host.rules`, Codex | FAIL | `no AGENTS.md at the root …` | `npx cookwright init` |
| `host.rules`, Codex | WARN | `Codex reads … in place of the AGENTS.md beside it` | **stop at**: explain that Codex reads that `AGENTS.override.md` instead of `AGENTS.md` in its directory |

### Session-start hook

| check | status | note | remedy |
|---|---|---|---|
| `host.hook` | FAIL | `no doctor SessionStart hook in …` | `npx cookwright init` |
| `host.hook` | WARN | `… has an earlier version of the doctor hook` | `npx cookwright init` |

### Skill and workflow pointers (`host.pointers`)

| status | note | remedy |
|---|---|---|
| FAIL | `… missing (run npx cookwright init)` | `npx cookwright init` |
| FAIL | `… missing (run npx cookwright init)`, after init printed `pointer … not written: this filesystem refuses symbolic links (…)` | **stop at**: this filesystem (exFAT, some network mounts) refuses symbolic links, so init cannot write the pointer and the line does not clear; cookwright's backlog tracks it as B-010 |
| FAIL | `… missing (run npx cookwright init)`, after init printed `pointer … not written (…); whatever stood there is unchanged` | **stop at**: init could not write in that directory (its permissions, or a disk error, as the code in brackets says); fixing that is the developer's, then `npx cookwright init` again |
| FAIL | `… is an earlier pointer` | `npx cookwright init` |
| WARN | `… does not point where cookwright is installed` | `npx cookwright init` |
| WARN | `…: not installed where it points (npm install)` | `npm install` |
| WARN | `… is ignored by git; git add -f … to track it` | with consent, the `git add -f <path>` the line names |
| WARN | `… (Level 2) not required at level 0 …` | **stop at**: a Level 2 piece they removed; say `npx cookwright init` would write it back |
| WARN | `… missing: pointers are symbolic links, which cookwright does not support on Windows …`; on Windows also `… is your own; it shadows cookwright's …` for a pointer the repo commits (git checked the link out as a text file) | **stop at**: explain that Windows is not supported in this version; cookwright's backlog tracks it as E-029 |
| WARN | `… is your own link …`, `… is your own; it shadows cookwright's …`, `… is a link of yours …` | **stop at**: explain that cookwright's skill or workflow is unreachable under that name while theirs is there |

### Git hooks

| check | status | note | remedy |
|---|---|---|---|
| `hooks.path` | FAIL | `core.hooksPath is not set …` | `npx cookwright init` |
| `hooks.path` | WARN | `… hooks are managed elsewhere …`, `… cookwright's hooks are not installed` | **stop at**: explain; offer the one-line call of the README's "Hooks managed elsewhere" for their own hook |
| `hooks.pre-commit`, `hooks.pre-push` | FAIL | `… missing`, `… is not executable` | `npx cookwright init` |
| `hooks.pre-commit`, `hooks.pre-push` | FAIL | `… is not a file; move it aside …` | with consent, move it aside, then `npx cookwright init` |
| `hooks.pre-commit`, `hooks.pre-push` | WARN | `… node_modules/cookwright is not installed here …` | `npm install` |
| `hooks.pre-commit`, `hooks.pre-push` | SKIP | `hooks managed elsewhere` | follows `hooks.path` |
| `tools.gitleaks` | SKIP | `skipped, needs gitleaks, run setup …` | give the install command, the developer's hands (`brew install gitleaks`; on Linux their distribution's package or the release binary; on Windows `winget install gitleaks`), then doctor again |
| `tools.gitleaks` | FAIL | `gitleaks does not run (exit …)` | **stop at**: show the line (a malformed `.gitleaks.toml` is the usual cause) |

### Gate (`gate.scripts`)

| status | note | remedy |
|---|---|---|
| FAIL | `gate check "…" runs npm script "…", which package.json does not define …`, or `…, but there is no package.json at the root …` | name the script; with consent, add it to `package.json` or fix the check in `gate.checks` |
| PASS | `no gate checks configured` | at the end (see "At the end") |

### Secrets (`secrets.env`)

| status | note | remedy |
|---|---|---|
| FAIL | `tracked env file(s): …` | **stop at**: never open the file; say untracking it and rotating what it holds are the developer's to do, and that Level 2 replaces env files |
| WARN | `… at the root: a plaintext env file …` | **stop at**: never open the file; say Level 2 replaces it |
| WARN | `… not ignored by git` | `npx cookwright init` |

### Doctor itself

| status | note | remedy |
|---|---|---|
| FAIL | `the check could not run: …` | **end**: a bug in cookwright; show the line |
| SKIP | `unverified: …` | run doctor once more; if it repeats, **stop at** it (git or a tool did not answer in time) |

## Adding a host

With consent, add the host (`claude`, `codex`) to `hosts` in `cookwright.json` by hand (init never edits an existing config), then run `npx cookwright init`, then the loop. For Codex, say to trust the hook in Codex with `/hooks`, and again after any rewrite of `.codex/hooks.json`.

## At the end

- Read the last readout's PASS lines once for the two that carry advice, and act on each that is there:
  - a Codex `host.hook` line reading `whether it is trusted is yours: /hooks`, when init wrote or rewrote `.codex/hooks.json` in this walkthrough: say to trust the hook in Codex with `/hooks`, and again after every rewrite of that file;
  - a `gate.scripts` line reading `no gate checks configured`: say pre-push runs nothing, and offer a gate check (`npx tsc --noEmit`, `npx expo lint`, their call), written into `gate.checks` with consent.
- Print the level line and the `next:` line of the last readout.
- Name every file init, migrate or you wrote in this walkthrough, so the developer commits them by path (`git add <paths>`, never `-A`).
