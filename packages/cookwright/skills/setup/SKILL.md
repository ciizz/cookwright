# setup — Level 0

**Doctor is the state; this skill keeps none of its own.** Every decision below is made from a doctor readout taken after the last thing you changed. The logic lives in the CLI (`npx cookwright …`); this skill only says which command answers which line.

It is reached once `npx cookwright init` has run (init writes the pointer that makes this skill visible), so a repo without `cookwright.json` starts from the README's quick start, not here.

## Rules

- Never write a plaintext env file (`.env`, `.env.*`), not as a fallback and not for a test, and never open one.
- Never put a secret's value in the transcript, a doc, a commit or a log. Name the secret instead.
- Never `git commit --no-verify`, never `git add -A`.
- An install outside the repo (`brew`, `apt`, `winget`, a host update) is the developer's hands: give the exact command, never run it. A change to `package.json`'s dependencies is asked for first.
- "With consent" below means: say what you will change and why, and wait for a yes.

## The loop

1. Run `npx cookwright doctor` and read the whole readout: one line per check (`STATUS  check  note`), then the counts, the level line and the `next:` line.
2. Take the first line that is not PASS and that you have not already stopped at in this run. Find it in the recipe below by its check, its status and its note.
3. Apply exactly one remedy, show the command's own output lines, then go back to 1. Never act on a readout taken before the last remedy.
4. **A remedy that does not clear its line.** When the remedy refuses (it exits non-zero, or prints an `init: …` or `migrate: …` refusal), when the next readout shows the line as it was, or when the developer declines it, show the command's output and the line, and **stop at** that line: never apply the same remedy to the same line twice in a run. One exception: a refusal that names a file to fix by hand (`… is not valid JSON (…); fix it by hand, then rerun`, `… is not the shape … reads …; fix it by hand, then rerun`, `… is a symbolic link and init does not write through one …`, `… exists and is not a file; move it aside, then rerun`) makes that fix the next remedy: show the refusal, make the fix it names with consent, then go back to 1.
5. Stop when every line is PASS, or when every line left is one you stopped at: explain each of those in a sentence and take no action on it. Then do what "At the end" says, which covers the PASS lines that carry advice.

A line the recipe does not name: show it, say this skill has no recipe for it, and **end** the walkthrough there. Never improvise a remedy. A line that **ends** the walkthrough also ends it.

With several hosts, a host check's note is one part per host (`claude: …; codex: …`); take each part as its own line.

## Recipe

### `config`

| status | note | remedy |
|---|---|---|
| WARN | `valid at version N after migrating from M in memory; run npx cookwright migrate to write it` | `npx cookwright migrate` |
| FAIL | `version N is newer than this cookwright's M: update cookwright …` | ask first, then `npm install cookwright@latest` |
| FAIL | any other line (the file is invalid) | show the line; fix the key it names in `cookwright.json` by hand, with consent |

Doctor refusing with `no cookwright.json at or above …` → `npx cookwright init`. While `config` FAILs, the other checks read SKIP `config invalid`: they follow from it, so fix `config` first.

### `git`

| status | note | remedy |
|---|---|---|
| FAIL | `not a git work tree` | **end**: init and every hook need a git repo; `git init` is the developer's call |
| WARN | `baseBranch X does not exist` | with consent, create the branch, or set `baseBranch` in `cookwright.json` to the branch they merge into |
| SKIP | `skipped, needs git, run setup` (on any check) | **end**: git is not on PATH; give the install command for their platform |

### One declared pack's rows (`pack.<name>.…`)

Each pack in `packs` adds its rows after the others: `pack.expo.declared`, `pack.expo.rules`, `pack.expo.docs`, `pack.expo.lint`; `pack.supabase.declared`, `pack.supabase.rules`, `pack.supabase.docs`, `pack.supabase.lint`, `pack.supabase.types`. A `.lint` row appears while one of the pack's ESLint rules is on, `pack.supabase.types` while its `types` rule is on. `pack.expo.declared` and `pack.supabase.declared` always read PASS, naming the pack's version and rules: nothing to do. A note can carry several of the parts below, joined by `; `: take each part as its own line.

`npx cookwright packs rules` prints the declared packs' doc-sync rules and gate checks as JSON, `{ "docSync": […], "gate": […] }`. Where a remedy below writes one of them, copy the entry from that output into `hooks.docSync` or `gate.checks` of `cookwright.json` as printed, never retyped; an entry of the same name that is the developer's own is theirs to rename first.

### Doctor itself

| status | note | remedy |
|---|---|---|
| FAIL | `the check could not run: …` | **end**: a bug in cookwright; show the line |
| SKIP | `unverified: …` | run doctor once more; if it repeats, **stop at** it (git or a tool did not answer in time) |

## Adding a host

With consent, add the host (`claude`, `codex`) to `hosts` in `cookwright.json` by hand (init never edits an existing config), then run `npx cookwright init`, then the loop. For Codex, say that Codex reads `.codex/hooks.json` only at startup: restart Codex at the work tree's top, trust the hook there with `/hooks`, and the readout comes in the next new session; the same restart and trust again after any rewrite of that file.

## At the end

- Read the last readout's PASS lines once for the one that carries advice, and act on it when it is there: a Codex `host.hook` line reading `whether it is trusted is yours: restart Codex, then /hooks`, when init wrote or rewrote `.codex/hooks.json` in this walkthrough: say that Codex reads that file only at startup: restart Codex at the work tree's top, trust the hook there with `/hooks`, and the readout comes in the next new session; the same restart and trust again after every rewrite of that file.
- A `pack.supabase.types` line reading `measured by the gate against the local stack`: say the gate's types check regenerates the types from the local Supabase stack, so it measures only while that stack runs (`supabase start`) and skips, naming why, otherwise.
- With a pack declared, offer each of these in turn, each with consent, the developer free to decline any:
  - **The gate checks.** Every `gate` entry of `npx cookwright packs rules` whose name is not in `gate.checks` (the `standards` ratchet among them), added as printed. Their exit 11 is "cannot measure", recorded as skipped (`skipExit`), never a failure.
  - **Doc-sync rules from the tree.** A doc under `docs/` whose name matches a code directory (`docs/api.md` beside `src/api/`) is a candidate: show each, and add the ones the developer keeps to `hooks.docSync` under a name of theirs (never a pack's `expo:`/`supabase:` name), for instance `{ "name": "api", "code": ["src/api/**"], "docs": ["docs/api.md"] }`.
  - **Filling a contract doc.** When a `pack.<name>.docs` line named entries missing from its doc, offer to fill it from the code: on a new branch (`git checkout -b docs/fill-<doc name>`, never on the base branch), add one entry per primitive or migration that has none, in the doc's own shape (a table row, or a `## <Name>` or `### <Name>` heading when the doc is written that way) (the line shows the first few names; list them all from the code directory), each read from its file, in this session, then `npx cookwright doctor` until that line reads PASS. Then, with consent, commit the fill by path on that branch (`git add <the doc> && git commit -m "docs: fill <the doc> from the code"`), so the tree is clean, and when the `docs-audit` skill is installed, run it on that branch to verify the fill (its step 2 stays on a `docs/fill-<doc name>` branch it is handed); otherwise say the commit is the developer's to review. A declined commit leaves the fill uncommitted: say the audit needs a clean tree, so it waits until the fill is committed.
- Print the level line and the `next:` line of the last readout. A level line reading `not verified: …` names the required checks that could not measure (a tool not on PATH, as their lines say): the level is not complete until they measure.
- Name every file init, migrate or you wrote in this walkthrough and did not commit (a fill committed above is not among them), so the developer commits them by path (`git add <paths>`, never `-A`).
